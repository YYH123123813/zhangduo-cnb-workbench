# 应用与回顾

节点五负责把一次知识使用的原情境保存下来，并提供可选的、由服务端记录事件的学习回顾。
本模块不生成正式知识、不训练模型、不计算掌握率，也不直接修改其他模块。

## 当前交付边界

**未运行测试、类型检查、构建、浏览器、探针或外部请求**；源码接线不等于现有 live
进程已升级，更不等于学习场景的 live 或 G3/G4/G5 验收。

| 路径 | 当前边界 |
| --- | --- |
| 应用记录 | use/outcome 接共享批准、私有 EvidenceStore、原操作回执和历史读取。 |
| 人工回顾 | 审核题目录、可信 attempt、信心/提示/揭示/提交/取消/反馈/申诉接共享 S07。启动仍须通过真实能力和精确题目版本校验。 |
| 模型辅助评阅 | 仅保留内部适配器；没有生产私有作答 reader 或学习模型 HTTP/UI 入口，缺来源时明确拒绝。 |
| 长期学习证明 | 30 天 S07 保存不等于 until_deleted 学习档案。平台仍拒绝 recall/near_transfer 的长期 EvidenceRecord 写入，不提供客户端绕行。 |

`client_preview_only` 只说明保存了人的使用情境；`self_reported` 只说明用户自报结果。
服务端持久回执证明的是原操作已应用，而不是知识正确、学习有效或用户已经掌握。

## 应用记录操作

1. 从检索工作区进入，核对原任务、条件三态、节点和 Git 版本、正式关系路径、覆盖警告。
   共享导航只传白名单 ID/版本；临时 `retrieved` 丢失时回原任务重新检索，不把新文字绑回旧 query。
2. 明确选择采用、不采用或待验证。默认不选；有限制的采用须填写理由。不记录也可返回任务。
3. 预览原任务、知识条件/边界、路径、决定与理由。语义覆盖 unavailable 不等于 Git
   原文完全不可用，但工作区、固定快照、排除清单、正式关系和条件校验不能省略，警告不能隐藏。
4. 单独勾选长期私有保存同意，再「登记保存批准」，核验批准登记后才「保存应用记录」。
   原 operationId、完整记录 hash 和 baseRevision 固定；批准不是保存成功。
5. 读取原记录。后续可选择该 use，填写达到目标、未达到目标或尚不清楚、结果说明与失败原因，
   另行预览/批准/保存独立 outcome。outcome 必须绑定原 `useRecordId`，始终标自报。
6. 保存失败结果后，通过「复核原版本」进入版本与数据工作区。共享链接使用
   `nodeId/revision/useId/evidenceId/taskId`；`useId` 对应原 use，`evidenceId` 对应结果记录。
   修改前提、关系或知识后回原任务重查，旧 use/outcome 不改写。

use 的 `useContext` 保留完整 task、snapshotRevision、知识内容/条件/边界、关系、路径、
coverage/warnings/missingConditions 和 reason，不塞进 answer。当前共享 use schema 没有
独立 taskRevision/taskContentHash 字段；不伪造字段。它保存的是经记录摘要绑定的原 task
副本；S07 start 则显式发送共享任务存储的 revision/hash 并由服务端原子绑定。

## 题库准备

由运行维护者在取得授权后准备服务端私有审核题，不在浏览器、Git 正式知识或本模块内另建题库。
共享 runtime 的 `ZHANGDUO_REVIEW_CATALOG_FILE` 指向 `.local/<mode>/<name>.review.json`；
文件必须为非符号链接、0600 私有普通文件且不超过 1MB。导入绑定已验证工作区和独立
operationId、30 天确认，最多 100 题；同题 ID/revision 内容不可变。

每题包含精确 nodeRef、题目 revision、回忆/近迁移类型、审核人/时间、私有标准答案、三级提示和
版本化 rubric。近迁移还须明确改变的条件与必要前提，不能只换数字。上述是现有平台要求，
不是授权本轮创建目录、导入题库或触发连接。导入原文件及 SQLite/WAL/备份物理擦除另行核验。

页面只读取 approved 的公开题目投影，不获取标准答案、完整 hints 或私有 rubric criteria。
readReviewRuntime 的 ready 还不够，必须再匹配本节点、本知识版本、题 ID 和题 revision；
空目录、未配置、缺端口、非法 DTO、越权及版本不符均不启动。

## 回顾操作

1. 自愿开启临时队列，先单独保存原任务 30 天，或只读恢复并核对已经保存的原任务。
   不在 start 前静默 GET 新任务替换原确认；另一会话把 A 改 B 后，A 的 start 必须冲突。
2. 加入所选知识，读取该版本审核题，再单独同意本次作答、提示、反馈与申诉私有保存 30 天。
   队列最多五项，可跳过、延后、移除或关闭；队列本身不持久化，不自动提醒或开题。
3. 选择题目，先记录低/中/高/跳过信心，再开始作答。信心是自报，开始后不能改成作答前事件。
4. 可逐级申请提示或显式查看答案。共享 S07 先持久化暴露和事件回执，再交付允许的文本；
   未到阶段不能把答案放在 HTML、隐藏 DOM、题目录或多余网络响应里。
5. 提交后显示原作答和允许的答案/评分项，逐项人工评阅、逐字引用作答并说明判断。
   可修正反馈、标题目无效或独立提交申诉。取消本次编辑不删除原作答，之后可继续人工评阅。
6. 已提交/已核验取消的会话可以返回回顾队列；在途/unknown 先核验原事件，返回不创建下一题。
   「退出本次验证」是独立 cancel 事件，不等于物理删除或撤销已发生的答案暴露。

生产初始暴露为 unknown，`unassistedCertification=false`。没有看到页面答案不能推导未暴露；
提示、原文浏览或看过答案后，不宣称无提示掌握。`met_rubric` 只表示本次人工评分项判断。
当前页面尚未选择/传入 `priorRecallAttemptId`，而平台要求近迁移先有同任务/同知识版本、
无暴露的已提交回忆。正常运行 unknown 不能满足该资格，**近迁移主线尚未交付**；不得伪造
unexposed 或仅凭客户端分数放行。该差额与人工回忆路径分开验收。

## 同意与保存期限

| 对象 | 独立确认 | 期限与删除边界 |
| --- | --- | --- |
| 临时预览/回顾队列 | 不默认落库 | 当前页面内存；离开受保护，未同意不暗存浏览器。 |
| 原任务 | 任务保存确认 | 共享任务存储 30 天；有独立 revision/hash 和原操作回执。 |
| 审核题 | 服务端人工审核与导入确认 | 30 天；不是作答者点开始就批准导入。 |
| attempt/事件/反馈/申诉 | 本次作答保存确认 | 30 天，原始期限不由恢复延长。到期/删除可清理正文，最小操作元数据不等于正文。 |
| use/outcome | 具体内容的 save_evidence 批准 | 私有 until_deleted，不入语义索引；每个结果另行确认。 |
| 跨刷新恢复身份 | 下一次操作单独勾选，默认关闭 | 最长 24 小时；只有原身份、操作 ID、摘要、版本等最小元数据，不含正文或批准载荷。 |
| 模型输入 | 独立目的、范围、预算和批准 | 本模块生产入口未接；不能用上述任何保存同意替代模型发送授权。 |

## 历史与未知恢复

任务、证据、S07 事件、modelPurpose=review 分别使用自己的原 operationId。每个学习事件有
独立 requestHash、attemptId、expected/resultingVersion；feedback/appeal 再绑定反馈版本。
页面展示核验过的原事件回执，当前版本可更高，但版本增长不能证明本次操作成功。

刷新/重新连接后，经同意保留的 recoveryIdentity 先核对当前身份/工作区、原 ID/hash/期限，
再读专用回执。默认只读元数据；用户另行点击才读当前有权的正文，包括可能已揭示的答案。
task 已变化时只承认原回执，不展示新任务冒充历史；原批准正文丢失不能用当前任务重建。
unknown、null、mismatch、过期、失权不能触发自动 POST、再批准、继续作答、揭示或下一题。

保存已核验但正文被拒绝时，只显示回执，不再呈现该保存面板里的旧预览正文。历史知识入口
按原完整 Git 版本读取，并前后核对当前权限及删除屏障；旧记录未保存的条件显示 not_recorded。
删除屏障不因普通 Git 恢复解除，应用阻断不宣称页/WAL/备份已擦除。

1.26 恢复入口及身份卸载已有共享接线；1.31 请求级 Session Binding 在当前 api-client 只覆盖
intelligence。学习及其 workspace 请求的跨标签 Cookie 换身份窗口仍需窗口一统一处理和验收，
不是要求重建恢复存储。无预先独立同意时，不能承诺强制刷新后仍找回未保存的唯一身份。
