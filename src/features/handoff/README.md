# 人工交接与知识入库

节点三把已授权的对话现场整理为人的正式知识。AI 只提供候选；人的表达、来源支持、条件判断、正式关系、私有草稿和 Git 提交分别记录，不用一个“已确认”状态代替全部事实。

本说明按当前源码契约 `1.31.0` 静态整理。**本轮没有运行测试、类型检查、构建、浏览器、探针或真实写入**。历史测试结果不证明本轮修补已验证，也不代表所有刷新、身份切换或真实 CNB/Git 场景通过。接口细节见 [API.md](API.md)，交付状态见节点三任务包的 `03_交付报告.md` 和 `04_接口申请.md`。

## 入口与前提

- AI 候选入口：`#handoff?conversationId=<现场ID>`；可用 `candidateId` 定位单项。候选是原现场的提议，不默认采用。
- 纯手动入口：`#handoff?conversationId=<现场ID>&source=manual`。不读取候选、不调用模型；先选本次原句范围，再生成独立空白审阅。
- 私有进度入口：`#handoff?conversationId=<现场ID>&draftId=<草稿ID>`。只能读取当前身份有权访问且未过期的已存进度。
- 原操作入口：带 `changeSetId` 的地址进入只读核验，不加载最新可变草稿重建旧提交。完整地址还携 `draftId/source/operationHash`，这些参数不是权限或批准。
- 正式入库前，现场必须为 `saved` 且 `sourceAlreadyPersisted=true`。仅能读取 Issue、或仓库是 Private，不等于已经取得草稿、批准、Git 或索引写权限。

平台必须提供可信会话、私有持久存储和正式知识快照。权限至少包括 `conversation:read`、`draft:read`、`draft:write`、`knowledge:read`；AI 路径另需 `candidate:read`；正式预览和知识批准/提交需要 `knowledge:write`。索引更新使用独立 `knowledge:index` 和批准流程，由工作区入口负责，不随交接自动触发。节点三不启停服务或替用户配置凭据。

## 人的审阅责任

1. 每项独立选择“开始交接”“只保留现场”“拒绝候选”或“稍后处理”。取消选择回到未判断，不提交。后三种选择不新增正式知识；要跨会话保留选择，需要另行保存进度。
2. 通过“当前审阅”切换条目，文字、条件、来源判断及未完成关系输入按项保留在内存。没有明确保存的内容，不能承诺刷新后恢复。
3. 核心陈述默认空白。自行输入为 `human_written`；原样采用 AI 文字为 `ai_accepted`；在已接受 AI 文本上修改为 `human_edited`。这些是表达来源，不是掌握或正确性评分；系统不能识别所有外部复制行为。
4. 手动审阅填写标题、对应问题与知识类型。当前 AI 路径沿用原候选的标题/问题/类型，不在本轮另造元数据编辑模型。
5. 填写一项关键前提、来源条件或适用边界，明确选择成立、未核验或不成立。留空/未知不会变成成立；未知条件可保留并在预览中提示，拒绝条件或不支持来源使知识需要复核。
6. 对照自己的陈述与每条来源原句，选择支持、部分支持、不支持或未核验。部分支持必须填写范围限制；只有链接、没有原句，不能确认为支持。改写陈述会清除旧支持判断，改条件/边界/来源会使关系重新待审。

来源 ID、原句、UTF-16 左闭右开偏移、共享 `hashConversation/hashSegment` 和来源版本在服务端核对。来源改变、偏移不匹配、同 ID 指向不同原文、无权访问等情况不能靠手动勾选绕过。正式知识仍可能带未核验来源；人的确认并不补足缺失证据。

## 正式关系

先读取知识版本，再选择同工作区、已确认、有效且未排除的目标。关系需要方向、目标版本、理由、可核对的来源依据和一次明确确认；零关系是合法选择。

| 界面关系 | 正式枚举 | 方向含义 |
|---|---|---|
| 支持 | `supports` | 来源端支持目标端，不自动证明目标为真 |
| 依赖 | `depends_on` | 结论指向其必要前提 |
| 冲突 | `contradicts` | 保留所选存储方向，不自动新增反向边 |
| 替代 | `supersedes` | 新结论指向被替代结论，不抹除旧历史 |

`conflicts_with` 不是当前正式枚举。模块阻止跨工作区、悬空、自指、重复、旧版本、失效目标和未经确认的关系进入正式预览；共享 Git 文档校验还阻止替代关系成环。当前模块没有单独的循环可视提示，不能把共享最终拒绝描述为前端已预先识别全部循环。

## 草稿、快照与 Git

| 保存对象 | 触发动作 | 含义与限制 |
|---|---|---|
| 本地编辑 | 输入/切换条目 | 只在当前 Page 内存；没有暗存浏览器正文 |
| 私有进度 | 明确同意后“保存审阅进度” | 空白/部分/完整输入共用 `ReviewProgress`，最长30天；不写 Git 或索引 |
| 完整草稿 | 公共 draft API | 与进度共用 CAS 版本线；不含未完成关系表单，不能代替进度保存 |
| 原提交快照 | 预览后另行同意“保存本次原预览” | 固定原 draft、changes、source、savedDraft、版本/摘要、理由与时间；最长30天且不超过原草稿期限 |
| 正式知识 | 独立批准，再“提交到 Git” | 以固定 ChangeSet 和基准版本请求 `Services.commit`；只有可信回执才显示 Git 已保存 |

保存进度前先读取知识版本、已存进度与私有版本。保存携带原 `operationId`、来源摘要、`expectedRevision/expectedContentHash`，由平台执行原子 CAS。冲突保留本地编辑，先比较，再明确选择采用平台版本或以对照版本保存本地内容；不会最后写入覆盖。知识基准变化时，保留文字、清除本次关系并按新版本重审是显式动作。

本地导出由人点击触发，仅导出当前项及其关联原操作资料，可能包含原句、批准载荷和未知回执元数据。它不是脱敏公开包，不是服务端保存，也不是可直接导入执行的批准。请按私人文件保管；模块不导出其他条目的正文或令牌。

## 批准、取消与未知结果

- 预览不保存、不登记批准、不提交。返回修改使当前预览失效；已有批准须先确认撤回，未知撤回只允许核验原批准。
- 保存原快照、登记知识批准、Git 提交是三个独立动作。保存回执或固定地址不等于批准。
- 批准绑定原 actor/workspace、用途、对象范围、内容摘要、基准版本和期限。正文或版本改变不能复用旧批准。
- 进度保存、原快照保存、批准登记/撤回、Git 提交任一结果未知，保留原 ID 与对应状态，走原操作 GET 读回；不自动重发保存、批准、Git 或模型请求。
- `null`、`missing`、`not_registered` 不证明未提交。只有平台明确记录的终态可以解除相应未知；Git 事实必须独立核验。
- 取消只读恢复使迟到读取结果失效，不撤回远端批准，也不取消已发出的写入。离开保护不能保证浏览器强制终止时保住未保存正文。

## 固定地址与原 A 恢复

原预览保存且核验回执后，“固定当前操作地址”只调用 `NavigationProps.pinHandoffOperation`。摘要来自原 `changeSetHash`，并经共享 `hashChangeSet` 重算，必须为64位小写 SHA-256。节点三只传 `conversationId/draftId/changeSetId/source/operationHash`，不写 history、不用 localStorage/sessionStorage，也不把正文、Token或批准载荷写入 URL。

本轮静态修补使当前实例的固定地址回调不再触发现场重载；摘要计算复用同步请求门，迟到结果不能写回已卸载实例。dirty、pending、unknown 和原批准仍由原状态及统一 leave guard 管理。实际 Page 挂载行为由共享 App 控制，**尚无本轮浏览器实测**。

强刷/新标签没有本地保留标记时，只读取该 ID 的不可变原快照，核对地址摘要和草稿/来源绑定，再分别读取批准与 Git 回执。另一会话把草稿保存成 B，不能用 B 补造原 A；恢复页不出现新的审阅、批准或提交按钮。过期、删除、失权、身份/范围/来源/摘要不匹配时不展示不可信正文；仍可尝试不依赖正文的 Git 元数据只读核验。

两个明确限制需窗口一处理：带 `candidateId` 的单候选地址目前会被共享 pin 保留额外字段，本模块暂拒绝原位固定并保留编辑，另提供五字段只读链接；跨标签 Cookie 换身份时，当前共享请求绑定只覆盖 `/api/intelligence`，handoff 请求尚需相同的执行前绑定和响应隔离。不能声称全部跨身份刷新场景已解决。

## 提交后的版本交接

可信回执显示原 ChangeSet、Git revision 和 Commit 链接。“查看对应知识”携 `nodeId` 与同一 `revision` 进入节点四。Git 已保存与 `indexing=pending/current/failed` 分开；索引等待或失败不会触发第二次 Git 提交。当前回执未携带最新索引核验结论时，不能自行把 pending 改成 current；检索覆盖和索引授权在节点四/工作区独立处理。

## 可并入根 README 的纯人工主线

本节是用户流程说明，不是已验收的 live 演示记录；本轮未改根 README。

1. 在同一掌舵工作区连接获得授权的私人仓库，由维护者确认后端、会话、存储和权限条件。只读连接不能代替写入授权。
2. 在“对话现场”选择允许保留的内容，核对范围并完成现场保存及读回；不启用 AI 提取也能继续。
3. 从手动整理入口进入“知识交接”，选择本次原句范围，点击“从所选原句开始空白审阅”，对本项选择“开始交接”。
4. 填写标题、对应问题、分类与自己的核心陈述；填写关键条件及适用边界，不确定就保持未核验。
5. 逐条核对原句、支持范围与限制。读取当前知识版本后，按需添加支持/依赖/冲突/替代关系，明确方向、目标版本、理由和依据；无关系则保留零关系。
6. 读取已存进度与版本，另行同意私有保存并保存本条审阅。发生 CAS 冲突时先对照；结果未知时只核验原保存操作。
7. 查看入库差异。需要跨刷新恢复原操作时，另行同意保存完整原预览并核验，再固定原操作地址。未完成原快照保存或地址固定，不承诺强刷能自动定位该提交。
8. 明确登记本次知识批准，然后另点“提交到 Git”。未知响应只读回原 ChangeSet，不重发。
9. 取得可信 Git 回执后，点击“查看对应知识”，由节点四读取同一 revision；索引尚未同步就显示等待，不把 Git 成功写成向量索引成功。
