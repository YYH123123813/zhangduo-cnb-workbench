# 对话现场

把用户选择的一段现场留在 CNB，再决定只归档、人工整理或提取待审候选。入口为统一导航的「对话现场」；本模块不直接写入正式知识或关系。

本机静态核对日期：2026-09-16（Asia/Shanghai），源码契约 `1.31.0`。**静态检查，未运行测试**；接入状态沿用 integrated，不代表本次修改通过运行验收或全局 G0-G5 完成。接口明细见 [API.md](API.md)。

## 输入与操作

1. 填写当前问题，可附最多 5 条约束；未知条件不要填成已确认。选择「只归档」或「归档后提取AI候选」。空问题可留临时草稿，但不能保存为有效现场。
2. 选择「粘贴对话」「手动记录」或指定当前仓库的 CNB Issue 编号。粘贴和手动记录先本地解析；Issue 读取只针对指定编号，不遍历历史，不访问粘贴的任意外部链接。
3. 勾选要保留的片段，核对角色。未能证实角色时保留「来源 / 角色不明」。切换来源、角色或内容会使原预览失效；未选片段不会装入保存或模型请求。
4. 检查敏感内容提示。疑似密钥必须遮盖，个人信息单独核对；可增加指定片段的字面遮盖。看原文与处理后的内容，再点击「核对本次内容」。检测不是绝对无遗漏保证。
5. 点击「生成保存预览」，核对工作区、片段、内容摘要和新现场身份，再点击「确认保存至CNB」。已有 Issue 作为来源时也创建新的选定副本，不覆盖原 Issue。
6. 等到按原现场 ID、内容摘要和保存位置读回一致后，才显示已保存。到此即可结束；现场归档不是正式知识，也不会自动调用模型。
7. 需要跨页保留任务时，独立点击「核对任务保存范围」，查看完整任务并勾选私有保存 30 天，再保存任务。随后读取任务还需明确点击「使用已存任务」，不会自动覆盖当前问题。
8. 本页刚保存的现场，且权限、AI 设置和候选状态满足条件时，可以选择模型片段、预览模型输入，再单独确认发送并保存候选 7 天。模型输入限当前问题、约束和本次勾选的已保存片段，不含未选原文或整库资料。
9. 对已读回候选点击「审阅此候选」，进入人工交接。AI 关闭、未配置或已确认零候选时，可直接「手动整理」；人工路径不制造 Candidate。未决操作先核验，不能用手动链接绕过离开保护。

来源解析最多 100000 个 UTF-16 字符、200 个片段；模型文本最多 24000 字符，且须满足共享模型输入 schema 的范围限制。超限拒绝，不静默截断。手动遮盖最多 50 条规则。

## 三类同意

| 明确动作 | 同意范围 | 不代表 |
|---|---|---|
| 确认保存至 CNB | 当前预览的选定脱敏现场、新 Conversation / Issue | 保存任务正文、发送模型、正式知识入库 |
| 确认保存任务 | 完整 TaskContext 私有保留 30 天 | Issue 保存批准、模型发送批准 |
| 确认发送并保存待审候选 | 当前模型输入的 extract 用途及候选私有保留 7 天 | 正式表达、关系确认、Git 提交或训练同意 |

范围选择、用途单选和隐私核对不是平台 Approval。保存与模型分别登记不同的 operationId；服务端再次核验身份、权限、用途、摘要、版本、期限及撤回状态。

## 权限与保存

| 行为 | 所需能力 |
|---|---|
| 工作区状态 | `workspace:read`；AI 设置显示还需要 `settings:read` |
| Issue / 已保存现场读取 | `conversation:read` |
| 保存并读回现场 | `conversation:write`、`conversation:read`，可信批准及受控私有仓库 |
| 任务保存 / 恢复 | `task:write` 和 `task:read` / `task:read`；结构化知识条件还受共享知识权限约束 |
| AI 提取及候选落盘 | `conversation:read`、`model:extract`、`settings:read`、`candidate:read`、`candidate:write`，可用模型与共享存储 |
| 模型原操作发现 / 恢复 | 共享工作区、模型和来源读取权限；候选正文另受 `candidate:read` 约束 |
| 手动交接入口 | 现场读取权限；审阅保存、正式提交的额外权限由节点三校验 |

| 数据 | 位置与期限 |
|---|---|
| 未确认任务、原始粘贴、未选片段、遮盖规则 | 当前页面内存；刷新或确认离开后可能丢失，无 localStorage / sessionStorage / 私有数据库 |
| 确认保存的现场 | 指定 CNB 仓库的新 Issue；本模块未提供自动到期删除，取消不会删除原 Issue 或已保存副本 |
| 确认保存的任务 | 共享 TaskStore / SQLite，30 天；到期停止提供正文，不等于备份、WAL 已物理抹除 |
| AI 候选批次 | 共享 CandidateStore / SQLite，7 天；空批次也有原批准及 revision，到期不重提取覆盖 |
| 批准、操作与回执元数据 | 共享 OperationJournal / SQLite，按平台策略管理；不是草稿备份，不含可供重放的模型输入或输出 |

实际 SQLite 文件由共享 runtime 配置，受控路径为 `.local/live/*.sqlite` 或 `.local/fixture/*.sqlite`。本模块不配置第二数据库。原始现场、任务和候选不直接进入正式 Git 或语义索引；后续正式化、索引及训练各有独立流程和授权。

## 候选与关联边界

模型只能给出 0 至 3 条 `proposed` 候选，分类为概念、事实候选、主张、原则、方法、决策或问题。正文、保留理由、不确定项均需符合 schema；额外指令、工具调用、伪造 ID / hash / 人工确认等字段拒绝。

每个引文须来自选中片段，UTF-16 偏移左闭右开、逐字匹配且不拆代理对，并核对现场及片段 hash。这里的原句是**已保存脱敏副本**中的原句，不冒充脱敏前原 Issue 的逐字引用。来源支持初始为 `unverified`，引用存在不等于主张成立。节点二不生成或提交正式关系；关系与人的表达由人工交接另行审阅。

## 错误与只读恢复

| 状态 | 用户可做什么 |
|---|---|
| 加载 / 核验中 | 等待或停止等待；不连续发起写入 |
| 未配置 / 无权限 | 保留本地编辑，交维护者核对配置或权限；不能靠修改参数绕过 |
| 非法输入 / 敏感内容 | 修正范围、问题或遮盖后重新预览 |
| 冲突 | 保留编辑，读取并明确采用新版本后重新预览；不覆盖他人版本 |
| 批准登记未知 | 核验原登记；只有本页保留完整原载荷、确定尚未执行且原批准有效时才可明确继续 |
| 保存 / 模型 / 候选写入未知 | 按原 ID 只读核验，不能再次建 Issue、申请新批准或重发模型 |
| `model_done` / `candidate_saving` | 尚未取得候选终态，保持未决；不是失败或允许重试 |
| `rejected_without_save` | 必须同时有平台拒绝终态及候选 missing；按平台原因显示，允许人工继续，不重发原模型 |
| `saved_empty` / `saved_nonempty` | 核对原批准、批次 revision、数量和候选摘要后完成；零候选不是未发送 |
| 取消 | 只停止后续动作/等待，已发出的操作仍可能完成；撤回批准也不能撤销已完成副作用 |

保存回执按 conversationId 恢复。统一模型恢复必须使用**原批准登记 operationId**，再以返回的实际 approvalId 查询提取状态。缺失原登记 ID 时，按 conversationId 发现原操作，由用户选择具体项；发现结果中的提取 operationId 在当前契约中是实际模型批准 ID，不能混作登记 ID。

离开保护接共享导航：未保存编辑需要确认，原批准或执行未知保持 blocked。普通 hash 导航和浏览器关闭/返回的具体交互仍需运行验收；没有承诺强制刷新可恢复未同意保存的正文。

## 交接地址与已知缺项

- 现场读取：`#capture?conversationId=<id>`；任务可用已有白名单 `taskId`。
- 原模型恢复：`#capture?conversationId=<id>&approvalId=<original-registration-operation-id>`。`approvalId` 是历史 URL 键名，不是该值的类型说明。缺原登记 ID 时只给现场发现入口。
- 候选审阅：`#handoff?conversationId=<id>&candidateId=<id>&source=candidate`。
- 人工整理：`#handoff?conversationId=<id>&source=manual`。
- 不向 URL 传任务、对话、候选正文或批准对象；不引入节点三的私有实现。

当前共享缺项已登记到本节点 `04_接口申请.md`：W2-REQ-010 原 Issue 描述/版本的持久来源绑定；W2-REQ-011 AI 对话归档入口到首次提取的安全许可；W2-REQ-012 节点三消费已同意保存的任务及批次身份核验。已存现场的手动入口存在，但不能声称完整任务及原 Issue 元数据已经贯通。

刷新或从 AI 对话归档进入的旧现场不会因为 candidates missing / 发现空列表自动开放新模型发送。当前无安全首次提取依据时可只读查看或人工整理，不重新归档来绕过。窗口一已记录真实 CNB 只读和部分浏览器证据，但 Issue `invisible` 校验未通过；本模块不放宽写入门禁，也不宣称 live 保存、模型或 G5 已验收。

## 给根 README 的使用段落

以下可由窗口一或其文档负责人直接并入根 README，本节点不修改根文件：

> 在「对话现场」填写当前问题，选择 CNB Issue 或粘贴文本，勾选有价值的片段，核对角色和脱敏结果，再预览并确认保存。任务正文如需跨页保留，须另行同意私有保存 30 天。保存后可以只保留现场，或使用「手动整理」进入人工交接；本次提取条件满足时，也可单独预览并批准模型输入，候选私有保留 7 天且必须经过人工审阅才可能成为正式知识。出现保存或模型结果未知时，只核验原操作，不重复保存、重新批准或重发。未选原文及未同意保留的任务不会暗存浏览器；刷新和 AI 对话归档入口不因候选为空自动开放新模型发送。真实环境的写入和模型调用分别需要授权。
