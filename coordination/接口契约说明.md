# 六窗口共享契约 1.31.0

1.31.0 兼容增加 `X-Zhangduo-Session-Binding` 请求/响应头。AI 页面经共享壳层绑定已核验的 actor、完整工作区和排序 scopes 的 SHA256；服务端仅与可信 Cookie/Bearer 会话比较，不从此头建立身份或权限。旧标签 Cookie 换人时在业务执行前拒绝，客户端拒收未回显或已卸载身份的响应。无此头的既有服务端工具协议不变；旧后端未支持回显时，新网页 AI 请求失败关闭，不误报可用。B/C/D 冻结实现无需改 DTO 或私自接入。细节见本轮 A 接口公告。

1.30.0 在用户授权的 AI 接入专项中兼容新增 `GET /api/intelligence/operations/:id` 和 `IntelligenceOperationSchema`，按原 actor/workspace/operationId 返回原请求摘要、动作、目标和最小结果，不返回私人正文；not_found/unknown 不能作为未执行证明，不重发。`IntelligenceMutation` 用 operationId 区分变更与只读命令。训练记录可选 `cleanupReady` 只在进程已核验停止时为 true，未知中断不能删除或自动重跑；overview 可选 `samplesStatus` 明确表示正式知识尚未就绪，但不阻断对话和模型配置。C 负责消费者实现，D 负责用户说明。细节与验收见 `AI接入并行/A/接口公告.md`。

1.29.0 增加同一掌舵系统内的 AI 对话、模型来源与用户权重设置、离线 Transformer/LoRA 调度。契约位于 `src/contracts/intelligence.ts`，通过既有 Services、可信会话、批准、Issue/Git 存储、人工交接和图谱检索集成，不替代业务模块。完整原文、正式知识和模型权重分层保存；smoke 只用合成数据且不可启用，lora 使用明确选中版本和可核验来源。接口/框架完成不代表真实 CNB 写入、生产模型质量或浏览器闭环通过。

1.28.0兼容增加`NavigationProps.recoveryRequested?:boolean`，由合法恢复地址在PageOutlet派生；只是导航意图，不是可信身份/批准。四、五在首次null、等待、到期、失权时仍保留恢复模式，不挂载可发送的新操作入口。共享壳层对尚未取得匹配恢复身份的地址先显示blocked等待边界；普通地址false不受影响。恢复DTO在渲染前核对完整会话指纹、当前recoveryId、feature、actor/workspace和TTL，防止effect清理前旧元数据出现在新地址或新身份；索引面板也随身份指纹重建。影响一、四、五；不更改业务回执、保留同意或恢复权限。定向结果及消费者接入见窗口一公告。

1.27.0新增W08独立`knowledge:index`权限和`update_index`批准用途，范围为固定Commit中的精确白名单文件及其hash、工作区/操作者、选定Embedding模型和原operationId。正式Git准备同步生成白名单Markdown副本，不触发向量更新；另行preview/approve/execute触发受控CNB流水线。`readIndexOperation`只读核验原构建号及知识库元数据，未核验不得current，丢响应不得重发。默认关闭Issue同步、forceRebuild和ignoreProcessFailures，不删除真实库。影响一的共享运行/导航、三/六的Git生成副本及提交索引状态、四的覆盖解释；业务目录不由一代改。共享实现、工作区入口、定向证据及生产条件已见当日1.27公告；真实CNB与浏览器未验收，消费者不得固定成功值。

## 2. 对象流

```text
TaskContext
→ Conversation + Approval
→ Candidate[] + SourceSpan
→ HandoffDraft
→ ChangeSet + Approval
→ CommitReceipt
→ KnowledgeSnapshot
→ RetrievalResult
→ EvidenceRecord
→ 修订ChangeSet / DeletePlan
→ 新KnowledgeSnapshot
```

上下游用ID、版本引用和Services交换对象，禁止直接import另一个业务模块内部实现。循环是业务生命周期，不允许转化为代码循环依赖。

## 3. 必须一致的含义

- `id`是稳定对象ID；`revision`为真实Git版本或明确标记的测试版本。不能把记录时间冒充Commit。
- `workspaceId`全流程隔离；P0不允许跨工作区关系。身份从受信会话建立，不从请求体照抄。
- `confirmation`、`evidenceStatus`、`lifecycle`与独立`EvidenceRecord`分别表示人的确认、来源支持、知识状态和行为证据，不混成一条掌握状态链。
- `authorship=ai_accepted`表示人同意保留AI原文，不等于人写了原文。真正人写/改才记录human_written/human_edited。
- `Approval`字段的存在不代表批准有效：服务端还要匹配操作者、用途、内容摘要、基准版本、有效期和撤回状态。
- `contentHash`按UTF-8稳定序列化的受控载荷计算SHA-256；不能散列带随机顺序的显示字符串。窗口一提供统一函数，其他窗口不能自行发明摘要规则。
- `SourceSpan`的start/end按规范化片段的JavaScript UTF-16 code unit偏移，左闭右开；`quote === text.slice(start,end)`；修改片段必须生成新摘要和重新验证。
- 正式关系只有supports、depends_on、contradicts、supersedes。方向按source→type→target保存；冲突可对称查询，但不自动建立反向存储记录。
- 节点关系以正式关系集合为权威，Markdown中的关系段只作生成展示，不另藏一套可编辑关系。
- `mode=fixture/live/unconfigured`不能来自用户可伪造的参数；fixture必须显著标示，不访问真实CNB。

## 4. 接口错误

错误必须使用Result/ApiResponse。对外不返回内部堆栈、Authorization、Cookie、Token或完整私人内容。

| 错误 | HTTP建议 | UI必须说明 |
|---|---|---|
| NOT_IMPLEMENTED | 501 | 尚未实现，未写入 |
| NOT_CONFIGURED | 503 | 未连接工作区，未执行远程动作 |
| UNAUTHORIZED / FORBIDDEN | 401 / 403 | 权限不足；不得扩大读取范围 |
| VALIDATION | 422 | 指出字段和恢复方法 |
| CONFLICT | 409 | 基准版本变化；保留草稿并重新预览 |
| UNKNOWN_RESULT | 202或409，统一后固定 | 结果未知，需要读回；不能盲目重试 |
| UPSTREAM | 502/503 | 已完成部分、保存状态与可重试动作 |

## 5. 同意与存储

捕获、模型发送、Git提交、证据保存、导出、删除、设置分别取得所需批准。客户端预览不是服务端安全边界。写入结果超时先核验，重试复用同一个操作ID但不能越过变化后的版本或撤回批准。

只索引被允许的正式知识。原始Issue、候选、草稿、查询历史、使用及学习记录默认不入语义库。Git为正式知识事实源；短期候选/草稿/幂等状态可在受控操作存储中，不进公开构建产物。

## 6. 跨窗口链接协议

- 捕获完成：界面链接 `#handoff?conversationId=...`，窗口三通过Services读取。
- 提交成功：链接 `#retrieval?nodeId=...`，以CommitReceipt定位真实知识。
- 采用/回顾：`#learning?taskId=...&nodeId=...&revision=...`；不得在URL放私人正文。
- 修订：`#governance?nodeId=...&revision=...`，携带旧版本，不静默覆盖。
- 窗口一负责hash路由参数解析和页面调度；当前骨架仅有模块入口，参数路由由W12完成。窗口二至六通过本窗口报告提出需要的链接参数，不各写一套全局路由。

## 7. 并行期间的依赖策略

平台尚未ready时，每个窗口在**自己的测试文件**注入Services fixture，仅实现所需端口；未知端口仍明确返回NOT_CONFIGURED。不得修改共享services.ts来让自己的功能暂时通过。

fixture、端口单测与live集成是三种证据。测试通过不能直接写CNB已接通。任何大范围契约变更先停受影响节点，保留当前草稿，并由窗口一协调版本升级。
