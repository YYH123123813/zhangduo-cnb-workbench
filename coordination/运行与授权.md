# 单用户运行与授权

本说明的配置与存储基线为契约 `1.28.0`，保留既有运行规则，不作为所有能力的实时验收报告。当前源码 `1.31.0` 的新增页面、身份绑定和配置说明见 [根 README](../README.md)、[功能状态与接口接入](功能状态与接口接入.md)。

历史上已有按仓库限定授权的真实读取、空知识快照初始化和一条合成 Issue 写后读回；对外边界见 [验证记录](../docs/验证记录.md)，私人运行报告不随源码上传。单条 Issue 私密标记未核验通过，应用仍只读；该次授权不扩展为模型、索引、部署、删除或全部业务写入授权。新环境的合成演示按 [演示与复现](../docs/演示与复现.md) 操作；下文旧验证安排不代表已执行。

## 配置与启动

唯一工程`作品`，已有共享Web端口4312、API4313；其他窗口不另起服务器。无现有服务器时从工程根执行`pnpm dev`，启动器选取空闲端口对。Node需满足package.json约束；SQLite在当前Node仍提示实验性。

服务端读取项目`.env`与显式进程环境，环境优先；`.env`必须是非符号链接、权限0600且不超过32KB。文件和`.local`均禁止由Vite读取。未配置时首屏为连接状态，health不冒充CNB连接。

必需项目：

- `ZHANGDUO_MODE=live`，`ZHANGDUO_STORAGE_CONFIRMED=true`：明确接受私有操作存储。不会自动创建远端仓库。
- `ZHANGDUO_BOOTSTRAP_KEY`：服务端专用64位小写十六进制随机连接密钥。它不是CNB Token；只向本机连接表单输入，不放URL、localStorage或客户端构建。
- `ZHANGDUO_STATE_FILE=.local/live/operations.sqlite`：持久文件，目录0700/文件0600。CNB容器需要实际持久卷，不能把临时容器磁盘称为持久交付。
- `CNB_REPO_SLUG`、`CNB_TOKEN`、`CNB_TOKEN_SCOPES`、`CNB_LIVE_READS_FOR`：指定私人仓库与其读取授权。至少需要account-profile:r、repo-basic-info:r以核对身份，具体Issue/Git能力另需对应scope。
- `ZHANGDUO_APP_SCOPES`：服务端明确应用权限白名单，必含workspace:read，不接受`*`。`.env.example`默认为只读，允许保存草稿需draft:write，候选需candidate:write等；应用权限不替代CNB token scope。
- `API_PORT`、`WEB_PORT`：不同的1024-65399端口；当前仅绑定127.0.0.1。外网反向代理/HTTPS/部署另行核验授权，不自动公开。

Issue/Git写入另需`CNB_LIVE_WRITES_FOR=<精确仓库>`与对应token写scope。模型另需CNB_LIVE_AI_FOR、明确model、已授权CNB流水线和已核验输出限制；预算20次/UTC日、并发2次、每批准至多发送一次。知识库查询另需CNB_LIVE_QUERIES_FOR。上述变量表达操作人员已获得授权，不是自动替用户取得授权。源码Git同步不兼任任何业务授权。

## 连接与恢复

GET `/api/workspace/connection`只返回状态和缺配置项名，零账号访问。POST `/api/workspace/connect`只接受`{connectionKey,confirmed:true}`，需同源JSON；先核验CNB `/user`的id/username及指定仓库id/path/visibility_level=Private，才签发HttpOnly、SameSite=Strict、Path=/api的一小时会话。第三方身份/扩权字段拒绝，每分钟最多5次尝试，单次在途互斥。实际远端信息以本日官方OpenAPI字段核对，账号真实返回仍待授权核验。

各API请求先核对可信会话，再只读复核CNB身份及仓库。网络不可达不伪报已撤权；明确401/403或身份变更撤销本机旧会话。POST disconnect撤销全部本机session/context并清cookie，未知业务操作的原事实不被删除。浏览器刷新会复核有效cookie；服务重启不恢复旧cookie，重新连接同一身份后读取持久草稿/回执。私有数据库固定原账号及仓库，不得换令牌后把他人数据归给新身份。

令牌、权限、连接密钥或配置变化使旧context失效并撤销旧批准，需重启重新核验。在途模型仍由设置/批准/来源返回前校验丢弃；旧成功回执不因撤销消失。相同配置重启保留原批准状态和操作事实。密钥只进受限服务器HTTP/Git进程环境，不输出日志或响应。

## CI 与部署边界

根目录 `.cnb.yml` 只配置 `push` 与 Pull Request 的检查流水线：`pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm check:boundaries`、`pnpm test` 和 `pnpm build` 按顺序执行，前一步失败不会进入后续构建。流水线不导入 CNB Token、不连接私人工作区、不调用模型、不写 Issue/Git/索引、不删除、不公开，也不部署；CI 绿灯只证明源码检查通过。

部署必须在独立授权下配置目标环境、持久卷、HTTPS/反向代理、访问名单、日志保留、费用上限和回滚方式，并先确认稳定版本的 G0-G5 证据。没有这些输入时不创建部署流水线、不上传镜像、不改变仓库可见性；本地 `pnpm dev` 与已部署服务必须分别报告。

## 私有存储边界

SQLite迁移标记user_version=2；从v1兼容新增audit_operations关联表，旧事件不猜测补原操作ID，所有原正文/批准/回执保留。拒绝高于2的未来schema，旧版应用不能回退打开已迁移数据库；mode元数据不允许fixture/live混读。自动运行使用`.local/live`，测试注入模式使用`.local/fixture`。不清理别人的数据库。

候选7天、完整草稿/部分审阅/私有任务30天；保存时必须独立告知范围并确认。原提交快照固定原已存草稿版本，期限截至原草稿expiresAt，不续期，保存不等于知识批准或Git提交。每身份候选+草稿+任务+原快照共最多1000个活动条目、合计25MB；单批候选256KB、草稿500KB、任务100KB、原快照700KB，另受单行存储上限约束。到期读取时清理，生产启动及每60秒主动清除过期行内正文/片段，保留原操作hash/身份/版本以防重复。操作元数据当前无自动删除期限，不默称匿名；审计只列ID和状态及可信原操作ID，不含正文。SQLite页、WAL、备份与Git暂存物理残留不能通过该清理宣称抹除。

使用/结果证据平台已接线：独立批准明确`retention=until_deleted`后才能保存原task/知识条件/关系路径或自报结果。每工作区10000个不可复用记录ID、正文总计50MB、单条500KB；不进入Git/索引。正文、原回执、元数据审计同事务。显式删除只清除选定证据行内正文，永久访问屏障先安装，回执/摘要/ID仍在；不声称SQLite页、WAL或备份已物理抹除。消费者五的页面接入与六的历史/导出联调继续，不能因平台具备就认为用户主线已接通。

任务保存、不可变handoff原提交快照、原审计关联、受信学习回顾、治理原载荷、内容绑定演示导出和操作最小恢复元数据平台已接，消费者UI验收另见公告。节点五/六业务消费、受控索引更新、浏览器实机证据和真实CNB仍未关闭。停止方式为共享启动终端Ctrl-C，API关闭后释放SQLite连接；不删除状态文件作为重启方法。
