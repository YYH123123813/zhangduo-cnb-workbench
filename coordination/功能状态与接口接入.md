# 掌舵：功能状态与接口接入

本说明核对当前契约 `1.31.0`、真实页面/请求/Services 与独立隔离验收。它补充 [根 README](../README.md) 和 [API 接入指南](对话沉淀与训练接入.md)，不另建系统。对外证据范围见 [验证记录](../docs/验证记录.md)；原协作日志和本机运行记录保留本地，不随源码上传。

## 1. 从实际问题划分职责

掌舵要解决的是：把一段现场转成能检查来源、保留条件、在未来任务中使用并持续修订的知识。聊天、保存、确认、检索和训练是不同动作，不能用一个“成功”覆盖全部结果。

| 层次 | 保存或处理什么 | 权威边界 |
| --- | --- | --- |
| 原始现场 | 经同意保存的本机会话、另行归档的 CNB Issue | 保留原表达；模型回复不是人的陈述，保存不表示内容正确 |
| 正式知识 | Git 同一版本中的节点、条件、来源、正式关系和排除清单 | 人工确认后提交；向量正文和模型权重都不替代 Git 原文 |
| 应用与回顾 | 原任务、原知识版本、采用/结果、作答及暴露记录 | 保留产生时的条件；采用次数、得分和自报结果不直接证明掌握 |
| 推理与训练 | API 推理、本地受控训练及独立启用的适配器 | 只辅助产出；训练完成不自动确认知识或启用模型 |
| 身份与操作 | 服务端会话、权限、批准、原操作回执、恢复身份 | URL、客户端勾选和缺失回执不能替代服务端核验 |

因此，“功能可用”需要同时具备源码实现、匹配版本的运行服务、所需数据/资源及本次权限与同意。测试或真实操作证据是另一项，不能只凭按钮存在或配置 `ready` 判断。

## 2. 模式与当前实例

| 入口/模式 | 目的 | 不会自动完成的事 |
| --- | --- | --- |
| `pnpm local:start` / fixture | 用独立合成资料运行既有本机人工流程；不读取私人 `.env` | 不连接用户真实 CNB，不因为 `.env` 中有模型密钥就开始真实推理 |
| `pnpm dev` / 配置后的 live | 由维护者加载服务端配置、可信身份、持久存储和现有平台适配 | 连接只读仓库不等于获得 Issue/Git 写入、模型、索引、导出或删除授权 |
| unconfigured | 明确展示连接与配置缺项 | 不补造用户、知识、批准、模型回答或写入回执 |

已有项目服务时先复用，不再启动另一份。`local:status` 只识别该启动器托管的进程，“未托管”不等于没有服务。Node/pnpm 要求以 [package.json](../package.json) 为准。

历史真实环境的受限读回与未完成边界见 [验证记录](../docs/验证记录.md)，不作为当前服务已加载最新源码的证明。专用 fixture 的启动、地址核验与停止方式见 [演示与复现](../docs/演示与复现.md)，工具文件存在不算已启动。

源码现为 `1.31.0`，新增页面身份请求绑定。非 watch API 不会因保存源码而升级；新 AI 页面拒收没有身份绑定回显的旧 API。维护者须加载匹配前后端并重新建立可信会话；D 没有更新 live 实例，不能声称其支持所有新增页面操作。

真实 Issue #1 的正文已读回，但单条 `invisible` 标记未核验通过。仓库为 Private 不等于这一属性已通过。正式现场保存的私密校验仍保留，本机一次性初始化授权不扩展为全部写入授权。

## 3. 页面与共享服务

以下列出现有入口与源码接线，本轮实际验证范围单列在第 8 节。所有业务模块通过 [Services](../src/contracts/ports.ts) 和统一 HTTP 组合，不导入兄弟 feature 的内部实现。

| 页面 | 使用者流程 | 平台接入与必要条件 |
| --- | --- | --- |
| `#workspace` | 连接/断开、核对身份与模式、查看索引操作 | 可信会话、配置探针；索引使用独立 preview/approve/execute/read 接口 |
| `#conversation` | 新建与读取完整会话、逐轮发送、归档、删除、核验原操作 | `intelligenceCommand`；本机保存同意、每次模型发送同意和 Issue 归档同意分开 |
| `#capture` | 导入/粘贴现场、脱敏、保存、AI 候选或转手动整理 | `readIssue/readConversation/saveConversation`、候选存储、独立模型批准与提取回执 |
| `#handoff` | 候选审阅、人的陈述、条件/来源/关系、草稿、差异与正式提交 | 草稿及原提交快照、`approveKnowledge/commit/readCommit`；草稿保存不是 Git 成功 |
| `#retrieval` | 带任务条件查询、查看原文/来源/版本/图关系、可选来源化回答 | `snapshot/semanticQueryWithStatus`、受限 `complete`；语义不可用时如实保留 Git 覆盖边界 |
| `#learning` | 采用与结果、原任务保存、回顾/作答、反馈/申诉、修订交接 | task/evidence/review 端口；真实审核题目录、原任务版本和暴露状态不能由浏览器自造 |
| `#governance` | 版本与关系修订、恢复、显式导出、分层删除、设置、审计 | 治理批准、原子提交、设置 CAS、删除计划与逐层报告；不把阻断检索写成物理擦除 |
| `#intelligence` | 提供方、权重、样本/版本、训练、指标、启停与清理 | `intelligenceCommand`、`ChatGateway`、`TrainingExecutor`；合格 LoRA 只用于候选提取 |

原模块的请求、响应和更细的业务约束分别见 [capture API](../src/features/capture/API.md)、[handoff API](../src/features/handoff/API.md)、[retrieval 接入](../src/features/retrieval/README.md)、[learning API](../src/features/learning/API.md)、[governance 接入](../src/features/governance/README.md)。

## 4. 状态必须如何解释

下表是跨流程的解释原则，不是新增的通用状态 enum。接入时仍使用各领域 schema，不把一种流程的终态套到另一种流程上。

| 情况 | 应保留的事实与下一步 | 不允许推断 |
| --- | --- | --- |
| 未配置、未连接 | 展示缺项或重新核验可信会话；不开始业务动作 | 不能用 fixture 身份进入 live |
| 正在读取 | 保留对应对象和请求身份，等待或中止本次读取 | 不能把尚未读完当空库 |
| 空数据 | 只有授权读取成功且结果为空才展示空列表/无匹配 | 网络失败、失权、来源不可读不等于无数据 |
| 本地未保存 | 编辑仍在当前页面；普通离开按 guard 处理 | 不承诺强制刷新恢复所有未保存正文 |
| 已预览 | 当前人看到的内容、范围、版本可供确认 | 预览不是保存、批准或外部发送 |
| 已批准 | 服务端核对原对象、用途、摘要、版本与有效期 | 批准不是执行成功，也不授权其他用途 |
| 发送/写入/训练中 | 保留原操作身份，防止重复提交 | 关闭页面或请求取消不等于远端取消 |
| 操作成功 | 原回执匹配原操作；依领域读取实际对象/版本 | Git 成功不等于索引 current；train 命令成功不等于训练完成 |
| 版本冲突 | 保留可保留的本地编辑，读取新版本后重新比较与确认 | 不静默覆盖，不用新正文重建旧批准 |
| 失权、撤回、删除屏障 | 阻止后续越权读取/发送，保留允许读取的原操作信息 | 不换身份认领旧结果，不用旧向量绕过删除 |
| 身份或页面变化 | 使用统一导航与会话绑定，丢弃旧身份异步响应 | 不能把 actor/workspace 请求字段当登录凭据 |
| 结果未知 | 按原 operationId 和正确用途只读核验，缺证据继续 unknown | null、404、not_found、撤回、过期和普通错误都不是未执行证明 |
| 权威未发送 | 仅受限模型的匹配 close/read 回执证明 `not_sent` 时接受 | 不能给聊天、Git、归档或训练自行添加同名安全终态 |
| 部分完成 | 分别展示已完成与未知/失败的层；按原操作继续核验 | 不把部分删除、索引延迟或回执丢失报成全部成功 |

### 实际状态来源

| 契约 | 现有状态 |
| --- | --- |
| [ChatSchema](../src/contracts/intelligence.ts) | `ready / sending / unknown` |
| 同文件 `IntelligenceOperationSchema` | `not_found / pending / completed / failed / unknown`；`readOnly: true`、`absenceIsFinal: false` |
| 同文件 `TrainingRunSchema` | `running / completed / failed / interrupted / deleted`；清理还需核验 `cleanupReady` |
| [ModelOperationReceiptSchema](../src/contracts/model.ts) | `sending / done / unknown / discarded / not_sent` |
| [IndexStatusSchema](../src/contracts/indexing.ts) | `not_requested / approved / pending / current / failed / unknown` |
| [ApiError.dataState](../src/contracts/api.ts) | `not_written / preserved / partial / unknown`，与业务生命周期分开 |

模型统一恢复用**原批准登记 operationId**，专用模型回执读取用 **approvalId**；字段相似但不可互换。Intelligence 使用自己的原命令 operationId。恢复元数据不是原正文，当前 task、草稿或会话不能冒充历史批准载荷。

跨刷新恢复按模块能力处理：handoff 有原提交快照和受控地址固定；retrieval/learning 使用独立同意且有期限的恢复身份；AI 对话/训练的原操作核验不等于所有页面草稿都可跨刷新恢复。不能自加 localStorage 保存私人正文补齐表面效果。

## 5. 最小权限

配置样例 [`.env.example`](../.env.example) 默认只读，包含 `workspace:read`、`conversation:read`、`candidate:read`、`draft:read`、`task:read`、`knowledge:read`、`evidence:read`、`settings:read`、`audit:read`。其中 `evidence:read` 用于总览的已批准采用记录，`audit:read` 用于活动审计；漏配会产生真实权限错误，不能改成空列表隐藏。

样例不会给正在使用的 `.env` 或会话自动扩权。以下是在相应读权限基础上按功能增补的权限，不应全选；服务端还检查对象、保留同意、批准与版本。D 本轮没有修改样例或真实配置。

| 要启用的操作 | 额外应用权限/条件 |
| --- | --- |
| 新建本机会话、保存/归档现场 | `conversation:write`；会话保留与归档各自同意，CNB 写入另需仓库写授权 |
| 逐轮 AI 对话 | `conversation:write`、`model:answer`、已配置的所选提供方、每次 `modelConsent` |
| 保存候选、审阅草稿、原任务 | 分别 `candidate:write`、`draft:write`、`task:write`，以及各自保留范围确认 |
| 正式知识/关系提交及修订 | `knowledge:write`、可信知识/治理批准与明确 Git 基准版本 |
| 候选提取、来源化回答、模型评阅 | 分别 `model:extract`、`model:answer`、`model:review`，还受独立治理开关、来源和模型批准限制 |
| 采用/结果、作答事件与反馈 | `evidence:write`；任务、题目、知识版本与专用操作回执校验 |
| 保存模型/权重设置、训练、启停适配器 | `settings:write`；训练还需样本读取、可用执行器及独立 `trainingConsent` |
| 受控索引更新 | `knowledge:index`、索引独立批准、精确仓库/模型/文件范围与流水线能力 |
| 导出、删除、审计 | 分别 `data:export`、`data:delete`、`audit:read`；导出与删除不是同一批准 |

应用 scope、CNB Token scope、按仓库的外部授权、界面本次同意是四层条件，不能互相替代。不提供“一键全部放开”命令。权限名以 [scopes.ts](../src/contracts/scopes.ts) 为准，配置规则见 [运行与授权](运行与授权.md)。

## 6. 接口扩展位置

已有接口是可注入的真实类型和调用位置，不是尚未实现的承诺。优先扩展适配器，不在业务模块或浏览器内复制存储、身份、批准逻辑。

| 接口/文件 | 当前方法与接入位置 | 扩展时保留什么 |
| --- | --- | --- |
| [Services](../src/contracts/ports.ts) | 业务端口；由 [createServices(options)](../src/platform/services.ts) 组合 | RequestContext、统一 Result、原操作身份、版本/删除屏障；无参数仍返回未配置 |
| [ChatGateway](../src/platform/ai-providers.ts) | `status()`、`send(provider, messages, structured?)`；`ServiceOptions.aiGateway` | 返回真实 text/modelId，未配置不回假文本；不把对话授权升级成仓库工具权限 |
| [ModelTransport](../src/platform/model.ts) | `mode`、可选 `ready(ctx)`、`complete(ctx, input)`；`ServiceOptions.model` | `BoundedModel` 的用途、来源、输出预算、批准、设置与模式校验；输出仍需 schema/引用核对 |
| [TrainingExecutor](../src/platform/training-runner.ts) | `ready/pretrainedReady/run/infer`，可选 `inspect/remove`；`ServiceOptions.trainingExecutor` | workspace/mode/run 隔离、选中版本、真实指标、进程核验；不得把未知进程标记成可删除 |
| [CnbClient](../src/platform/cnb/client.ts) / [GitPublisher](../src/platform/cnb/git-publisher.ts) | `ServiceOptions.cnb/git`，由 [createRuntime](../src/platform/runtime.ts) 接实际服务端配置 | 固定可信目标、最小权限、Git CAS、受限路径、写后读回；更换后端需维护者适配，不是任意 URL 开关 |
| [OperationJournal](../src/platform/journal.ts) | `ServiceOptions.journal`，持久操作、CAS 与事务 | live 不得混用 fixture，不能因重启清除原操作身份并重发 |
| [NavigationProps](../src/contracts/navigation.ts) | 统一 guard、handoff 地址固定、独立恢复身份 | 同页固定与页面离开分开；不在业务组件绕过导航直接改 history |

`aiEnvironment` 仅由服务端加载用户明确提供的配置。当前 `provider` 契约固定为 `cnb/openai/local`；新增第四种提供方须同时修改公共 schema、提供方能力与消费者，不是只加一个任意字符串。密钥不进 `VITE_`、URL、客户端构建或文档。

Python runner 固定使用 `training/.venv/bin/python` 和 `training/worker.py`；基础模型目录由 `ZHANGDUO_TRAIN_BASE` 配置。`ready/pretrainedReady` 是路径/文件能力信号，不保证依赖能导入或模型质量。训练说明只维护于 [training/README.md](../training/README.md)。

### 浏览器接入顺序

1. 把页面放进现有 App 和 `SessionRequestBoundary`，使用共享 [apiRequest](../src/app/api-client.ts)，从可信会话取得身份。
2. 先读当前能力、对象与版本。读取失败与空数据分开；1.31 AI 请求必须具有匹配的服务端身份绑定回显。
3. 将人实际看到的范围构造成公共 schema 接受的请求。变更保留稳定 operationId，需版本的操作绑定原 revision/hash，独立取得所需同意。
4. 通过既有同源 HTTP 发出一次操作，校验 envelope 与专用业务 schema。未知时走原操作只读核验，不生成新 ID 补发。
5. 提供方或训练器在服务端通过上述接口注入；加载匹配版本后验证真实能力。D 测试仅在外部传输/执行器边界注入 synthetic，不另写一套业务成功逻辑。

## 7. 明确不承诺的功能

当前没有即时取消训练、自动重跑、断点续训、自动下载/部署模型、任意云服务免适配替换、无限会话保留或所有草稿永久恢复。原操作核验不是通用撤销接口。

零权重不删除知识，停用不删除适配器，删除本机会话不删除已归档 Issue。应用检索屏障和训练目录清理不保证 Git 历史、SQLite/WAL、备份、外部模型或磁盘残留物理擦除。未来新增这些能力须有实际平台实现、权限和失败语义，不能先做一个假成功按钮。
