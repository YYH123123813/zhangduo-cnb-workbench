# 掌舵：对话沉淀与训练接入

本文面向使用者和接入现有网页的开发者。实现真源是 `src/contracts/intelligence.ts`、`src/contracts/api.ts` 和 `src/server/app.ts`；源码契约 `1.31.0`，包含共享页面身份绑定。部署授权与效果提升须另行核验。

**本轮为最终检查与交付整理阶段。** 对外结果和限制见 [验证记录](../docs/验证记录.md)，旧协作报告仅保留本地历史事实。合成模型/执行器验收不代表真实梯度或中文模型能力。

网页主导航提供「AI 对话」与「模型与权重」；后者包含「参数与权重」「训练记录」两个页签。完整功能入口见 [根 README](../README.md)，对应源码见 [功能状态与接口接入](功能状态与接口接入.md)。

跨全部页面的状态解释、最小应用权限、模型/训练/存储扩展位置集中在 [功能状态与接口接入](功能状态与接口接入.md)。该说明区分源码、配置、运行版本与实际证据，不以“接口已预留”代替可用性判断。

## 1. 先分清三个层次

| 层次 | 本项目负责什么 | 不意味着什么 |
| --- | --- | --- |
| 完整对话 | 本机会话保留用户和 AI 消息；另行批准后将当前现场存为私人 Issue | 未发送草稿不会因为建了会话而自动保存；保存不授权模型发送或训练 |
| 正式知识 | capture 候选或手动 handoff，经人核对陈述、条件、来源和关系后提交 Git；图谱参与检索 | 模型输出、关系路径、采用次数不等于真实性或掌握证明 |
| 推理与训练 | API 提供方用于推理；独立本地 worker 对已授权样本做加权 LoRA 训练 | 本工程不训练 OpenAI API 模型权重；本地权重不替代知识库、不保证逐字记忆 |

本项目的 OpenAI 路径是服务端 HTTP 适配器；`training/worker.py` 是另一个本地 Python 执行层。本文只描述这里的接线，不承诺外部提供方的模型可用性、价格、隐私保留或「最新」兼容性。第三方条款必须由用户另行核实。

```text
独立同意保存完整会话
  -> 每次独立同意把全部历史和本条消息发送给所选模型
  -> 独立确认归档当前现场到私人 Issue
  -> capture 候选或手动 handoff
  -> 人工核对与 Git 提交（节点、条件、来源、正式关系）
  -> 原有图谱检索 -> 有依据的采用/结果反馈 -> 人工修订
  -> 再次选择版本、调整权重、独立同意训练
  -> 独立评估 -> 单独启用候选提取适配器 / 随时停用
```

接入已有页面时复用 App 会话和同源 `/api` 代理，使用公共契约验证响应。不要直接把 platform/server 导入浏览器，也不要通过组件自己的 Token 或请求体里的 actor/workspace 建立身份。跨模块携带对象 ID 和版本，不在 URL 放正文、密钥或批准载荷。

`1.31.0` 中，App 的 `SessionRequestBoundary` 安装当前已核验的会话绑定；共享 `apiRequest` 为 intelligence 请求附带并核对 `X-Zhangduo-Session-Binding`。它是会话内容的摘要，不是 Cookie、密钥或授权凭证，服务器仍从可信会话鉴权。新增页面必须放在既有边界内，不能自行从 URL 拼身份。缺少或错绑回显的旧后端响应会被拒收；部署时须让前后端协议一致，不能删除请求校验来绕过。

## 3. 环境与启动

### 先核对当前服务

从克隆后的仓库根目录操作，先读 [演示与复现](../docs/演示与复现.md) 和 [运行与授权](运行与授权.md)。真实环境的单条 Issue 私密标记尚未核验通过，不是合成写入的测试靶场。`1.31.0` 新 AI 页面拒收旧后端缺失的身份绑定回显，非 watch API 不随源码更新。维护者须加载匹配版本并重新连接，不擅自启停他人持有的服务。

### 独立使用时的安装顺序

1. 准备符合 `package.json` 的 Node.js（最低 `22.13.0`）和 `pnpm@10.32.1`。不需要先购买 API 或下载模型。
2. 项目首次安装由维护者执行 `pnpm install --frozen-lockfile`。本轮协作中只有 A 安装依赖。
3. 仅想用合成数据检查人工流程，且已确认没有现有服务时，执行下面的本机入口。它不加载私人 `.env`，默认不接真实模型；不能靠给 `.env` 填 key 就改变这个合成入口。

```sh
node --version
pnpm --version
pnpm local:status
pnpm local:start
```

4. 打开启动器实际打印的 Web 地址；fixture 使用公开演示码 `LOCAL_DEMO_KEY`（64 个 `f`），live 使用用户自己的 `ZHANGDUO_BOOTSTRAP_KEY`。通过 Web 同源 `/api` 访问 API，不分别打开两个 origin 建立身份。fixture 不读取私人 `.env`；默认 interactive 实例若曾单独配置本地 AI profile，仍可能调用该模型，不能用于无条件的零外部调用承诺。
5. 真实工作区由维护者按下节配置服务端，再使用 `pnpm dev`。只设置 OpenAI/本地模型变量不能跳过可信工作区和 CNB 身份校验。真实仓库需要有效正式知识快照；仓库只有源码 README 不等于初始化了知识库。
6. 用户之后需要本地训练时，再按 [training/README.md](../training/README.md) 准备 B 指定的 Python 环境。runner 查找 `training/.venv/bin/python`；不要猜一个变量替换解释器。已有环境不重建，安装由 A 统一安排，真实梯度由 B/A 验收，D 不重复执行。

`providers[].ready` 和 `training.ready/pretrainedReady` 是配置能力信号，不是模型能正确回复、Python 依赖能导入或真实训练成功的验收证据。

### 只在服务端配置

只使用 [`.env.example`](../.env.example) 已有变量。不要读取或粘贴别的应用密钥，不在 issue、命令参数、截图、前端包或 `VITE_` 变量里放密钥。已有 `.env` 不覆盖；首次配置文件须普通文件、非符号链接、权限 `0600`，进程环境覆盖文件值。下列尖括号是用户填写的占位符，不能原样当作可用配置：

```dotenv
ZHANGDUO_OPENAI_API_KEY=<用户单独提供的服务端密钥>
ZHANGDUO_OPENAI_MODEL=<用户账号已确认可用的模型标识>
ZHANGDUO_LOCAL_AI_URL=<已有本机兼容服务的HTTP基础地址>
ZHANGDUO_LOCAL_AI_MODEL=<该服务实际提供的模型标识>
ZHANGDUO_TRAIN_BASE=<用户已准备的本地基础模型绝对目录>
```

未使用的提供方留空，不把占位符留在运行配置中。不要编造模型名，或把本地训练目录误填成 API URL。

| 选择 | 本项目实际读取与限制 |
| --- | --- |
| OpenAI API | 同时配置 `ZHANGDUO_OPENAI_API_KEY` 与 `ZHANGDUO_OPENAI_MODEL`；当前适配器固定使用 Responses 请求，并设置 `store: false`。工程没有 OpenAI 自定义 base URL 变量，也不据此保证第三方物理删除。 |
| 本地兼容 API | 同时配置 `ZHANGDUO_LOCAL_AI_URL` 与 `ZHANGDUO_LOCAL_AI_MODEL`；只接受 loopback 的 HTTP 地址，无用户名/密码、query 或 fragment。代码在基础地址后追加 `/chat/completions`；若已有服务要求 `/v1`，它须在基础地址里，不填完整 completions 端点。工程不会安装、配置或启动你的本地模型服务。 |
| CNB AI | `CNB_AI_MODEL` 及 `.env.example` 中对应仓库 AI 授权、流水线授权和输出限制核验项；缺任一能力就明确不可用。具体批准见运行与授权，不默认打开所有 flags。 |
| 本地 LoRA | `ZHANGDUO_TRAIN_BASE` 指向已准备的模型目录；worker 采用本地文件、禁止 remote code，runner 设置离线运行。支持的格式、模型要求、依赖和限制统一见 B 文档；不自动下载大型权重。 |

真实运行还需要已有的 `ZHANGDUO_MODE`、`ZHANGDUO_BOOTSTRAP_KEY`、`ZHANGDUO_STATE_FILE`、`ZHANGDUO_STORAGE_CONFIRMED`、`ZHANGDUO_APP_SCOPES` 和 CNB 仓库、令牌及独立读取授权。连接密钥不是 CNB Token。`.env.example` 默认应用权限是只读：

| 动作 | 应用权限边界（还需对象访问校验） |
| --- | --- |
| 总览 | `settings:read`、`conversation:read`、`knowledge:read`、`evidence:read`；可信会话还须 `workspace:read` |
| 创建/归档 | `conversation:write`；归档还需要读取与独立仓库 Issue 写授权 |
| 发送 | `conversation:write` 和 `model:answer`，外加本次 `modelConsent` |
| 保存参数/训练/启停 | `settings:write`；训练读取正式节点和来源还需相应读权限及 `trainingConsent` |
| 删除会话/训练产物 | `data:delete`；不是 CNB 远端物理删除授权 |

原 capture/handoff、Git 提交、使用/结果记录和受控索引还有各自权限及独立批准，不能仅靠以上几个开关越过。配置修改由维护者安排重启并重新连接，不自动扩权。D 本轮不读取真实配置、不安装、不启停服务。

## 4. 网页操作顺序

1. **连接工作区。** 先看 fixture/live 标记、仓库和权限。只读 live 不能保存现场或训练。不要将真实资料输入仅作合成验收的实例。
2. **保存会话。** 在「AI 对话」创建主题，明确接受本机完整会话 30 天保留。列表可读回已保存的用户/AI 消息；未发送的输入草稿没有持久保存承诺。
3. **单独发送。** 在「模型与权重」选择已配置的提供方并保存。每轮核对提供方、本条消息与全部历史范围，再同意发送。未配置时拒绝，未把本条冒充已保存/已回复；未知结果只读刷新，不再次点击发送补结果。
4. **归档现场。** 另行确认将当前全部消息写入当前私人工作区 Issue。成功后选择「审阅与 AI 提取」或「手动整理」。AI 提取还受原有治理开关与独立模型批准控制；会话发送同意不替代提取批准。
5. **人工沉淀。** 在 handoff 写自己的陈述，核对关键前提、边界和原句支持，逐条确认关系。保存草稿和批准 Git 提交是两个动作。看到真实 Commit 回执才表示正式保存；索引 pending 不等于 Git 失败。
6. **原图谱检索。** 从「知识与检索」查正式节点，展开实际关系路径、来源和端点版本。采用时保存当前任务和经批准的 use 证据；结果失败可进入治理修订。旧证据继续绑定原版本，不改写成新版本历史。
7. **权重与训练。** 修改参数后先保存，再选择当前版本的确认节点。新提交、撤回、删除或另一窗口改变设置时，重新读回、重新选择并确认，不自动替换之前批准的版本。
8. **评估与启停。** 训练完成不自动启用。smoke 永远不启用；合格 LoRA 也只在单独确认后用于后续候选提取，不接管聊天、不自动改写知识。停用适配器后回到所选 API；若 API 未配置，继续手动交接。

导航沿用 `#capture?conversationId=...`、`#handoff?conversationId=...&source=manual`、`#retrieval?nodeId=...`、`#learning?...` 和 `#governance?...`。这些是入口，不是完成证据。用户切换、断开或刷新后必须重新校验可信会话；不能沿用上一身份的内存草稿、同意和异步结果。

## 5. 权重与训练

个人知识 LoRA 的实际有效样本权重为（结果取三位小数）：

```text
importance = 节点覆盖值，否则 defaultImportance
weight = min(maxWeight,
  importance * (1 + reuseInfluence * ln(1 + 当前节点版本的已批准采用次数))
  * (human_edited ? correctionBoost : 1))
```

默认值 `defaultImportance=1`、`reuseInfluence=0.25`、`correctionBoost=1.5`、`maxWeight=6`。范围分别是 `0..5`、`0..2`、`1..3`、`1..10`；逐节点重要性 `0..5`，最多 1000 条覆盖；学习率 `0.000001..0.005`、步数整数 `5..200`。界面数值是样本贡献，不是知识可信度分数，不改检索的来源/版本规则。

- 零重要性样本不会进入本次 LoRA 数据集及 `nodeRefs`。它仍可保留于 Issue、Git 和检索，不会自动擦除已有模型的影响；需要停用旧适配器及按当前范围重新授权训练。
- 训练只读取选中、已确认、active、未排除的知识及可核对对话原句。缺原句支持、来源已撤回、版本不符会拒绝；不会默认拿全部私人会话训练。
- LoRA 有效非零样本必须来自至少两段不同原始对话，用于分开训练与验证；多选同一对话的节点不能冒充独立验证组。最多提交 100 个节点 ID。
- smoke 请求不选节点，只用内置合成数据与随机初始化模型，使用固定合成权重，只消费步数和学习率；它不证明当前重要性滑块的配置效果。真实梯度、权重效果和重载验证的口径见 [训练说明](../training/README.md)，注入执行器的测试指标不算真实训练。
- `running/completed/failed/interrupted/deleted` 是训练状态。运行中或中断未核验时不删除、不重跑；本接口没有可承诺安全终止的取消动作，停用适配器也不是终止训练进程。
- 启用须为 completed LoRA，重载验证成功，有独立验证组，前后验证损失非空且未退化，节点来源版本仍有效。损失下降只是门槛，不证明提取质量、知识正确或用户掌握。

训练细节仅维护于 [training/README.md](../training/README.md)。不要把训练产物放进 `public/`、`dist/` 或任何浏览器静态目录。

## 6. API 接入

### 可信会话与统一响应

浏览器先通过既有连接表单建立会话：同源 `POST /api/workspace/connect`，请求仅为 `{ connectionKey, confirmed: true }`，值来自用户当次输入，不在文档填真实密钥。服务端核验后签发 HttpOnly Cookie。之后读取 `/api/workspace/session`；不能在 intelligence 请求中加 actor/workspace、Token 或伪造权限。连接和断开属于独立会话接口，不要给它们硬塞 intelligence 的字段。

所有 intelligence 成功/失败使用以下类型结构，不是伪造的成功示例：

```ts
type Envelope<T> = (
  | { ok: true; data: T }
  | { ok: false; error: {
      code: string; message: string; retryable: boolean;
      dataState: 'not_written' | 'preserved' | 'partial' | 'unknown';
      nextAction: string;
    } }
) & { meta: { requestId: string; mode: 'fixture' | 'live' | 'unconfigured'; contractVersion: string } };
```

不要只看 HTTP 200，也不要把 `dataState:not_written` 当成另一个 operation 的结论。服务端实际错误映射包括 401/403 身份权限、422 参数、409 冲突或未知结果、503 未配置、502 上游失败。API 使用 `Cache-Control:no-store`。

下面代码是现有工程 `src/app/` 内、已挂载 `SessionRequestBoundary` 的页面接入模式；变量来自读回数据和用户确认的界面快照，每个变更由单独的事件处理器调用，**不是将所有示例串成一键自动执行**。实际面板优先复用 `intelligence-client.ts`，低层请求也必须复用 `apiRequest` 的页面身份与回显核对。未安装可信绑定时请求会被本地拒绝，不在独立脚本中伪造绑定。

```ts
import { IntelligenceCommandSchema, IntelligenceOverviewSchema,
  ChatSchema, IntelligenceOperationSchema } from '../contracts/intelligence';
import { apiRequest } from './api-client';

async function api<T>(path: string, body?: unknown): Promise<T> {
  const reply = await apiRequest<T>(path, {
    method: body === undefined ? 'GET' : 'POST',
    credentials: 'same-origin', cache: 'no-store', redirect: 'error',
    headers: { 'Content-Type': 'application/json' },
    ...(body === undefined ? {} : { body: JSON.stringify(body) }),
  });
  if (!reply.ok) throw new Error('先核验原操作；不自动重发');
  return reply.data;
}
const overview = IntelligenceOverviewSchema.parse(await api('/api/intelligence'));
// 仅在已选会话时读取，不能猜 ID。
const chat = ChatSchema.parse(await api(`/api/intelligence/chats/${encodeURIComponent(selectedChatId)}`));
// 原 operationId 来自本次已提交命令，绝不新建 ID 试探原结果。
const receipt = IntelligenceOperationSchema.parse(
  await api(`/api/intelligence/operations/${encodeURIComponent(originalOperationId)}`),
);
```

`GET /api/intelligence` 返回设置 revision、提供方能力、节点版本/有效权重、会话摘要与训练记录。`samplesStatus.state=unavailable` 表示正式来源暂不可核验，不是空知识库；聊天和设置仍可用，训练仍严格核验来源。`cleanupReady=true` 才允许清理终态产物。完整消息按 ID 读取。兼容只读命令还有 `POST /api/intelligence` 的 `{action:'overview'}`、`{action:'read_chat',id}`、`{action:'read_operation',id}`；不带 confirmed/operationId。

无页面绑定头的旧 HTTP/Services 工具仍保留兼容；这不表示新网页可绕开绑定。新页无可信绑定时不发送，回显缺失/错误时不解析私密响应正文。已发 POST 后失去绑定只能记 unknown，不能解释成未写入。同一身份普通刷新不卸载草稿；Cookie 的身份、工作区、权限或可见性变化均须重新核验。

### 创建、发送与归档

```ts
// 用户已独立确认保存完整会话 30 天后，生成并保留原请求。
const createRequest = IntelligenceCommandSchema.parse({
  action: 'create_chat', operationId: crypto.randomUUID(), confirmed: true,
  title: reviewedTitle, retentionDays: 30,
});
const created = ChatSchema.parse(await api('/api/intelligence', createRequest));

// 另一事件：用户已核对完整历史、本条消息、所选提供方并重新同意发送。
const sendRequest = IntelligenceCommandSchema.parse({
  action: 'send', operationId: crypto.randomUUID(), confirmed: true,
  id: chatShownToUser.id, expectedRevision: chatShownToUser.revision,
  text: reviewedMessage, provider: providerShownToUser, modelConsent: true,
});
const replied = ChatSchema.parse(await api('/api/intelligence', sendRequest));

// 另一事件：明确确认将该版本的全部消息存入私人 Issue。
const archiveRequest = IntelligenceCommandSchema.parse({
  action: 'archive', operationId: crypto.randomUUID(), confirmed: true,
  id: chatShownToUser.id, expectedRevision: chatShownToUser.revision,
});
const archived = await api<{ conversationId: string; issueNumber: number; taskId: string }>(
  '/api/intelligence', archiveRequest,
);
// 使用回执的 conversationId 进入 capture/handoff，不能把 chat.id 当作归档 ID。
```

标题 1..120 字符；发送文本 1..12000 字符。契约会话最多 100 条消息，当前发送器在已有 98 条时即拒绝下一轮，并有总文本预算；长会话应人工另开，不能静默截断历史。保存时间由原 `expiresAt` 决定，不以刷新或发送承诺无限续期。

### 设置与绑定训练版本

```ts
const settingsRequest = IntelligenceCommandSchema.parse({
  action: 'settings', operationId: crypto.randomUUID(), confirmed: true,
  expectedRevision: settingsShownToUser.revision,
  settings: {
    provider: providerShownToUser,
    weights: { defaultImportance: 1, reuseInfluence: 0.25, correctionBoost: 1.5, maxWeight: 6 },
    importance: importanceReviewedByUser, learningRate: 0.0005, steps: 30,
  },
});
const savedSettings = await api('/api/intelligence', settingsRequest);

// 独立训练确认后，从用户实际看到并选中的版本快照构造，不在提交前静默刷新替换。
const approvedSelection = structuredClone(selectedSamplesShownToUser);
const loraRequest = IntelligenceCommandSchema.parse({
  action: 'train', operationId: crypto.randomUUID(), confirmed: true, trainingConsent: true,
  expectedRevision: settingsRevisionShownToUser, mode: 'lora',
  nodeIds: approvedSelection.map((sample) => sample.id),
  nodeRevisions: Object.fromEntries(approvedSelection.map((sample) => [sample.id, sample.revision])),
});
const run = await api('/api/intelligence', loraRequest);

// smoke 是另一种独立选择，不携带私人节点。
const smokeRequest = IntelligenceCommandSchema.parse({
  action: 'train', operationId: crypto.randomUUID(), confirmed: true, trainingConsent: true,
  expectedRevision: settingsRevisionShownToUser, mode: 'smoke', nodeIds: [], nodeRevisions: {},
});
```

设置是完整对象替换，不是 patch。`expectedRevision` 在 settings/train 中是设置 revision，在 send/archive/delete_chat 中是聊天 revision，不能混用 Git SHA。`nodeRevisions` 则是已批准节点版本映射，不能只带 IDs。schema 对缺省映射的兼容不代表 LoRA 可绕过版本校验。

训练启动返回 running 记录；使用 `GET /api/intelligence` 中原 run ID 轮询状态。原操作回执 `completed` 只表示 train 命令已被接收处理，**不表示训练完成**。

### 启用、停用与删除

以下各对象分别由一次独立确认产生，之后单次发给 `/api/intelligence`；没有 required 的字段不要凭空加入，strict schema 会拒绝：

```ts
const activateRequest = IntelligenceCommandSchema.parse({
  action: 'activate', operationId: crypto.randomUUID(), confirmed: true, id: evaluatedLoraRunId,
});
const deactivateRequest = IntelligenceCommandSchema.parse({
  action: 'deactivate', operationId: crypto.randomUUID(), confirmed: true,
});
const deleteChatRequest = IntelligenceCommandSchema.parse({
  action: 'delete_chat', operationId: crypto.randomUUID(), confirmed: true,
  id: chatShownToUser.id, expectedRevision: chatShownToUser.revision,
});
const deleteRunRequest = IntelligenceCommandSchema.parse({
  action: 'delete_run', operationId: crypto.randomUUID(), confirmed: true, id: terminalRunId,
});
```

activate/deactivate/delete_run 当前没有 expectedRevision 字段，启用门槛、来源资格与运行状态由服务端核对。delete_run 的 id 必须是原 UUID。删除响应明确 `physicalErasure:false`；delete_chat 还明确 `cnbArchiveDeleted:false`。停用不是删除，删除训练不删除正式知识。

### 未知结果：只读核验

1. 在内存保留原请求的 `operationId`、动作、目标 ID、原版本和请求哈希。不要把完整请求、同意或正文偷偷写到 localStorage。
2. 同一可信 actor/workspace 下读取 `GET /api/intelligence/operations/:operationId`。核对 action、targetId 与 `requestHash`；哈希算法复用公共 `contentHash(IntelligenceCommandSchema.parse(originalRequest))`，不是鉴权凭据。
3. 回执 `pending/unknown/not_found` 都不允许新建 operationId 重发，`absenceIsFinal` 固定为 false。`completed` 也只证明该命令，继续读原 chat、原 run 或归档来源状态。回执不包含正文。
4. 归档未知时，服务端只读核对原现场和 Issue，不创建第二个 Issue；无法证实时保留待核验状态。模型结果未知时同样不能靠再次发送补齐。
5. 若刷新后原操作 ID 丢失，不猜测并重建变更。只读会话列表、训练记录及已知回执；缺证据交维护者核验。当前 intelligence 恢复协议没有承诺跨刷新持久保存新身份。
6. 明确冲突后重新读取只是为了重新审阅；必须先弄清旧操作，再由用户另行确认新的内容和版本，不做自动 CAS 重试。

## 7. 退出、停用与删除边界

| 动作/层次 | 实际边界 |
| --- | --- |
| 断开连接 | 走既有断开接口，撤销会话，不等于删除对话/知识/训练产物，也不是已发模型请求的撤回保证 |
| 停用 LoRA | 后续提取不用该适配器；不删除文件，不停止训练，不自动改变原 API 提供方配置 |
| 本机会话到期/删除 | 当前 30 天保留，读取时识别过期并清正文；删除行内会话不抹除已归档 Issue、Git、索引、模型提供方副本或 SQLite 历史页 |
| 归档 Issue 与 Git 知识 | 是独立存储层；通过原治理流程预览、批准、安装删除屏障及读回报告，不用 delete_chat 代替 |
| 零权重/节点撤回 | 零权重排除未来样本；撤回、版本变化或删除会阻止旧来源适配器使用。都不代表已经从历史模型参数反向擦除信息 |
| 删除训练记录与目录 | 仅本工作区对应 run 的样本、适配器等受控目录，自动停用该 run；保留最小状态。外部基础模型、缓存、备份、磁盘物理残留不保证删除 |
| 索引 | Git 与检索屏障是事实依据，旧向量物理残留与远端删除需另行核验，不将逻辑不可见当物理抹除 |

正式 runner 产物位于 `.local/<fixture|live>/training/<workspace-sha256>/<run-id>/`。不要手工批量删除这些目录来解决冲突或中断，不上传到源码或静态目录。停止服务由其实际维护者按所属启动器/原终端处理；仅启动器托管的本机实例可用 `pnpm local:stop`，不按端口盲杀，不删除数据库当作重启。

## 8. 故障处理

| 现象 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 未配置/503 | 读 connection、overview 的能力和缺项，检查服务端指定变量及工作区是否有效 | 在浏览器填 key、把 fixture 标成 live、伪造成功 |
| 401/403 | 重新核对当前会话、工作区、同源及最小 scopes；由用户另行授权需要的动作 | 加 actor/workspace 请求字段或全部权限绕过 |
| CAS/409 | 读原操作、当前设置/会话/节点版本，保留草稿后人工重新审阅 | 自动更新 expectedRevision 或 nodeRevisions 重发 |
| 模型结果 unknown | 保留已存消息，读原操作和 chat；未核验前阻止新发送 | 换 operationId、切提供方补发原历史 |
| 归档失败或未知 | 核对原操作回执和原 conversation；查看 D 接口申请是否仍有版本问题 | 因缺界面链接重复建 Issue |
| 无可训练样本 | 检查确认/active 状态、支持原句、零权重和至少两个不同对话组 | 将所有聊天自动当样本、伪造来源或验证组 |
| Python ready 但训练失败 | 读原 run，按 B 文档核对依赖、本地基础模型、格式和输入范围 | 用 D 合成指标证明真实训练、自动下载模型 |
| interrupted | 管理员先核对原进程是否已结束，保留原 run 身份 | 直接删除目录、重跑、虚构「已取消」 |
| LoRA 不可启用 | 核对模式、完成状态、重载、独立验证和当前来源版本 | 把 smoke 改名启用或降低评估门槛 |
| 训练后提取无合法候选 | 使用手动 handoff，核对 schema、原句与范围；必要时停用 | 自动写入正式节点，宣称 loss 降低即质量提升 |
| 当前 live 仓库缺知识快照 | 由 A 和用户确定明确初始化/写授权方案，保留既有文件 | 上传 fixture 快照覆盖私人仓库 |

## 9. 验收与证据

本轮允许必要的隔离测试。下列命令已作为 D 定向验收入口，精确退出码、结果与源码指纹见最终报告；不以文件存在、文档示例或历史测试数代替执行结果。

```sh
pnpm exec vitest run tests/integration/intelligence-acceptance.test.ts
pnpm typecheck
```

D 测试复用 `platformFixture`、`createApp/createServices`，数据库在内存，操作和 runtime 标识唯一；模型与训练执行器明确 synthetic，不运行 Python、不访问真实 CNB、不修改公共 fixture。正式节点经既有 capture/handoff/Git 路径准备，图谱检索断言检查实际关系路径及采用/修订反馈，不能把链接存在算通过。

工具 `tools/intelligence-acceptance.ts` 默认只有显式 loopback 地址的 health 读取；非 fixture 在连接前拒绝。`--chat/--train` 还需 `--allow-fixture-mutations`，由 A 先安排专用合成运行实例和授权。本轮 D 没有对当前共享服务运行该变更工具；其安全逻辑测试注入 HTTP transport，不代表监听端到端验证。

所有独立验收 JSON/日志保留在本机 `.local/fixture/intelligence-parallel/`，不覆盖旧证据，也不随源码上传。合成 HTTP/Services、真实梯度、浏览器视觉/键盘、真实 CNB 四类证据分别报告，对外范围见 [验证记录](../docs/验证记录.md)；不把历史或其他角色的结果转写成本次已执行。

本指南的提供方说明仅依据本工程适配器，不据此推断外部政策、模型兼容性或价格；本项目的 `store:false` 不是彻底删除证明。
