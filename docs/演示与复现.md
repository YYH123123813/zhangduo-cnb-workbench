# 演示与复现

所有命令都从克隆后的仓库根目录执行。不要求存在作者桌面的其他文件夹，不使用作者私人配置。

## 1. 安装网页依赖

需要 Node.js 22.13.0 或以上，以及项目固定的 pnpm 10.32.1。本地交付验收使用的准确版本见 [验证记录](验证记录.md)。

```sh
node --version
corepack enable
corepack prepare pnpm@10.32.1 --activate
pnpm install --frozen-lockfile
```

若已通过其他方式安装匹配的 pnpm，可直接执行最后一步。首次依赖安装需要网络；不要把可离线运行合成模型回复误解为首次安装不需要下载 npm 依赖。

## 2. 启动比赛合成演示

```sh
node --import tsx tools/intelligence-fixture.ts start
node --import tsx tools/intelligence-fixture.ts status
```

打开命令输出的 `web` 地址。启动器从本机 `4514` 端口开始选择空闲端口，将 Web 与 API 放在同一来源；以实际输出为准。使用新浏览器配置或独立无痕窗口，不复用真实工作区的会话。

这个演示入口使用正式网页、HTTP、Services、批准机制和隔离 SQLite；CNB 传输与模型回复是明确标记的合成适配器。它不读取私人 `.env`，不请求真实 CNB，不调用付费模型，默认不启动 Python 训练。

连接页勾选本机合成工作区确认，再点击“进入本机工作区”。当前 fixture 表单会自动使用公开演示连接码，不需要提供真实 Token。不要把演示连接码用于真实环境。

## 3. 建议的演示顺序

| 步骤 | 操作 | 应核对的事实 |
| --- | --- | --- |
| 工作区 | 确认连接、读取身份与数据模式 | 页面明确为 fixture，工作区与契约一致 |
| 对话 | 新建会话、确认本机保存、输入一段不含私人信息的内容并单独同意发送 | 消息按角色保留；回复标明合成，不能当作真实模型效果 |
| 归档 | 单独批准把已保存的现场归档 | 成功后可进入候选审阅或手动知识交接；草稿不混入归档 |
| 人工确认 | 核对陈述、条件、来源原句与关系，按页面批准正式提交 | 候选不自动入库；显示准确版本和结果状态 |
| 检索 | 搜索刚确认的主题并查看节点、来源和关系路径 | 来源与版本可追溯；没有正式关系时不假造图边 |
| 应用与修订 | 记录采用条件及结果，必要时进入修订 | 使用记录不等于掌握证明；旧引用保持原版本 |
| 模型与权重 | 调整设置草稿、选择样本、观察资源未就绪状态 | 未安装训练环境时明确不可训练，不伪造成功 |
| 治理 | 预览导出、撤回或删除范围 | 每种副作用独立批准；物理擦除限制明确 |

## 4. 停止演示

```sh
node --import tsx tools/intelligence-fixture.ts stop
```

该命令只停止此启动器核验为自己持有的进程。状态信息和合成数据保留在 Git 忽略的 `.local/fixture/`。不要按端口盲目结束其他服务，也不要删除作者原有运行目录。

## 5. 自动化检查

```sh
pnpm typecheck
pnpm check:boundaries
pnpm exec vitest run --maxWorkers=2
pnpm build
node --test tools/check-release.test.mjs
node tools/check-release.mjs
```

发布检查审计的是 Git 暂存/跟踪清单，要求使用完整克隆。解压源码 ZIP 后可运行前五项；ZIP 不带 `.git`，最后一项应在 Git 仓库内执行。测试使用合成边界，不应提供真实密钥，也不应指向私人工作区。

`pnpm build` 只构建前端，不会把带有数据库和服务端授权逻辑的应用变成纯静态站点。不能只上传 `dist/` 就宣称完成部署。

## 6. 可选训练验证

网页合成演示不依赖 Python。仅在用户决定安装训练环境后，参考 [training/README.md](../training/README.md) 创建隔离虚拟环境并安装固定依赖。

```sh
training/.venv/bin/python -B training/tests/run_tests.py --run-id reviewer-tests-001
training/.venv/bin/python -B training/examples/run_smoke.py --run-id reviewer-smoke-001
```

每次使用新的 run-id，不能覆盖旧证据。smoke 使用内置合成样本和随机小模型执行真实梯度更新，不下载预训练大模型，不允许启用为生产提取器。个人 LoRA 另需合法、已准备的基础模型及明确批准的知识来源。

## 7. 真实环境

真实 CNB 与模型环境不属于零配置演示。先阅读 [运行与授权](../coordination/运行与授权.md)、[配置示例](../.env.example) 与 [接入指南](../coordination/对话沉淀与训练接入.md)。真实令牌只在服务端配置，并按读、写、模型、索引等能力逐项授权。

真实 CNB 存在尚未关闭的隐私属性与端到端验收限制，不能把合成演示成功作为真实环境写入安全或生产就绪证明。也不要将 GitHub 源码仓库当作私人知识数据仓库。
