# 掌舵 · AI 对话与个人知识图谱

**掌舵是一个基于腾讯 CNB 的、人主导、AI 辅助的个人知识图谱系统。它把一次次 AI 对话转化为有来源、有条件、有关系、可追溯、可修订的个人知识，让对话的结果能够回到之后的学习与实际任务中。**

“掌舵”表达的是本作品的核心原则：人决定方向、判断和边界，AI 帮助整理、关联与查找。系统希望帮助使用者积累自己的理解，而不是只积累更多由 AI 生成的答案。

## 我的作品是什么

掌舵把 AI 对话、知识整理、图谱检索和应用回顾放进同一个工作台。用户可以与 AI 讨论问题，也可以手动导入对话；从中挑选值得保留的内容，核对来源、适用条件和自己的解释，再确认它与已有知识的关系。经过确认的内容形成正式知识节点，之后可以按问题检索、查看关系路径、记录使用结果，并继续修订。

它面向持续使用 AI 学习、研究和解决工程问题的人。作品关注的不只是“能否再次找到那段聊天”，而是三个更具体的问题：**这条结论为什么成立？在什么条件下可以使用？我是否能够在新的任务中解释和检验它？**

## 为什么要做这个作品

本作品从一个学习与工作中的问题出发：一次对话可以很快得到答案，但得到答案之后，原始背景、适用条件和判断过程未必被保留下来。等到下一次遇到相似问题，使用者可能又要从头询问，也可能在没有核对条件的情况下直接复用旧结论。

如果只做自动摘要，容易保留结论而丢失依据；如果只做聊天搜索，找到相似段落也不等于判断出它适不适用。因此，掌舵把重点放在**从对话到知识、从知识到使用、再从使用回到修订**的完整过程，并保留人的解释与确认环节。

这是作品的设计动机，不作为已完成大规模用户调研或已证明学习效果提升的声明。

## 为什么这样设计

### 1. 用 Issue 保存现场，用 Git 管理正式知识

原始对话和正式知识承担不同职责。Issue 保留用户批准保存的对话现场；Git 保存人确认后的知识节点、来源引用、条件和关系，以及它们的版本变化。两者分开，既能回看“当时到底说了什么”，也能区分“我现在正式认可什么”。

这样选择 CNB，不只是把代码托管上去，而是让它的 Issue、Git 和知识库进入作品的数据链路：现场有出处，知识有版本，检索可以回到依据，修改后仍能解释历史。

### 2. AI 提供候选，人决定什么成为知识

模型生成得流畅，不等于结论已经可靠。掌舵允许 AI 辅助提取和分类，但要求用户核对自己的陈述、来源原句、适用条件和关系，再批准正式入库。没有模型时，也可以沿用人工整理流程。

人工确认不是给 AI 答案盖一个“正确”印章，而是让使用者明确表达判断及其依据。人的确认、来源支持和实际效果仍然分别记录，不能互相替代。

### 3. 图谱参与检索，而不只是展示连线

仅凭关键词或语义相似度，不能判断一个方案的前提是否成立。掌舵把依赖、冲突、替代等正式关系用于检索和条件检查，让使用者不仅看到一条答案，还能看到它依赖什么、与什么冲突、是否已被新版本替代。

例如，合成演示中的“可以使用缓存”依赖“当前任务允许短暂旧数据”。再次检索缓存方案时，系统应把这个前提一起呈现，而不是把旧结论当成对所有任务都适用的建议。

### 4. 把知识放回任务中，让使用结果推动修订

看过答案、点击采用和真正能够独立应用，是不同的事情。掌舵提供使用条件、结果记录和回顾入口；如果知识在实际任务中不适用，可以回到原节点修订条件、关系或版本。

这也是作品应对“认知外包”的设计：让用户解释、判断、尝试和反思，而不是让系统替用户宣称已经掌握。是否真正改善学习效果，仍需要独立实验验证。

### 5. 本地加权训练是辅助能力，不替代知识库

作品提供本地 Transformer + LoRA 训练接入。用户可以对已确认知识设置重要性，并结合当前版本的批准采用记录与人工修订记录形成样本权重，在独立同意后训练候选提取适配器。

这样设计是为了探索让提取过程更贴近用户重视的内容，而不是把模型参数当成原文存档，也不是让重要性权重替知识的正确性背书。训练不会自动改写正式知识；合成 smoke 训练只验证机制，不能启用为生产提取器。

### 6. 把隐私、授权和退出放进每一步

保存对话、发送模型、正式入库、训练、启用适配器和删除数据具有不同后果，因此分别确认。密钥只保留在服务端；写入结果未知时核验原操作，不盲目重复发送；撤回、导出和分层删除保留明确边界。

用户能够选择不发送、不入库、不训练或停止使用某个适配器，是“人掌舵”的实际组成部分。系统不把逻辑删除说成所有平台、备份和磁盘历史都已物理擦除。

## 作品如何形成闭环

```text
AI 对话 / 手动导入
    → 确认保存范围与隐私
    → Issue 保留原始现场
    → AI 提出候选 / 人工整理
    → 人核对陈述、条件、来源和关系
    → Git 保存正式知识与版本
    → 图谱检索与条件检查
    → 任务应用、回顾与结果记录
    → 修订知识和关系，影响下一次检索
```

一句话概括：**掌舵要沉淀的不只是 AI 说过的话，而是使用者能够解释、查证、复用并继续修正的知识。**

## AI 对话、沉淀与训练

正常使用顺序如下。先在合成实例熟悉流程，真实资料另行确认工作区、权限与每次发送范围。

1. 先连接可信工作区。在「AI 对话」单独同意本机保存完整会话 30 天；每次发送再单独同意把本轮及全部历史发送给所选模型。
2. 单独确认归档到私人 Issue 后，进入「对话现场」提候选，或「知识交接」人工整理。核对自己的陈述、前提、原句和关系，再批准 Git 正式知识。
3. 回到「知识与检索」使用已有图谱路径；采用和结果记录需另行确认，失败可引出人工修订。使用次数不是掌握证明。
4. 在「模型与权重」设置重要性，保存版本后选择确认节点，另行批准本地训练。重要性为零排除训练，不删除知识、不提高可信度。
5. `smoke` 只验证合成数据训练结构，禁止启用；`lora` 使用用户已准备的本地基础模型。合格训练仍需单独确认启用，可随时停用适配器。

**API 模型、训练参数、知识库是三层。** 当前 OpenAI 选项用于 API 推理；本地 `Transformers + PEFT/LoRA` worker 用于候选提取训练，不修改 OpenAI API 模型的权重。原文、来源、Git 版本和显式关系仍是正式知识的依据，权重不能替代它们。

- 使用与接入：[对话沉淀与训练接入](coordination/对话沉淀与训练接入.md)，包括配置、启动、页面操作、完整 API 示例、未知结果核验和删除边界。
- 训练环境、文件格式与离线运行：[training/README.md](training/README.md)。真实梯度由 B/A 负责，D 的注入验收仅证明编排。
- 历史协作日志与私人运行记录保留本地，不随源码上传；对外范围见 [验证记录](docs/验证记录.md)，不把旧测试数当作本次通过。
- 当前接口以 [公共版本](src/contracts/domain.ts)、[操作契约](src/contracts/intelligence.ts) 和 [接口契约说明](coordination/接口契约说明.md) 为准。`1.30.0` 增加原操作回执，`1.31.0` 增加页面身份绑定；旧版本与历史测试数不能替代本次验证。

架构中的数据流为：

```text
AI 对话 -> 独立归档 -> CNB Issue 原始现场
                         |
                 AI 候选 / 人工整理
                         |
                  人工确认与批准
                         |
           Git 正式节点、条件、来源与关系
                  |                  |
             图谱检索            选择版本与权重
                  |                  |
           应用记录与人工修订     独立批准本地 LoRA
                                     |
                              训练记录与评估指标
                                     |
                            单独启用为候选提取器
```

没有配置模型时，页面不伪造回复；没有训练环境时不启动训练。仅配置模型密钥并不能替代可信工作区连接。密钥只在服务端，配置项仅从 `.env.example` 选择，不使用 `VITE_` 密钥。

## 接入现有网页

本工程已把这些功能组合进现有掌舵，不需要新建第二套应用。下面是接入位置与配置顺序。

1. **沿用网页入口。** [App.tsx](src/app/App.tsx) 已挂载「AI 对话」和「模型与权重」，对应 `#conversation`、`#intelligence`。前者复用对话面板，后者复用参数与权重、训练记录两页签；原有捕获、交接、图谱检索和治理页面继续保留。
2. **保留共享会话与请求层。** AI 页面在 `SessionRequestBoundary` 内使用 `intelligence-client.ts`，底层请求经过 `apiRequest`，统一走同源 `/api`。不要把两个面板单独搬到没有可信会话绑定的页面，也不要在浏览器另存 API 密钥。
3. **沿用后端组合。** [服务入口](src/server/main.ts) 将 `runtime.services` 注入 `createApp`；其中已注册对话、设置、训练和原操作回执接口。不要用默认的未配置 `createServices()` 替代实际 runtime，也不要把 `src/platform/` 或 Python worker 打进前端。
4. **按需配置 API。** 先准备可信工作区，再按下方配置表选 CNB AI、OpenAI 或本地兼容 API。网页显示服务器实际报告的模型与就绪状态；留空的提供方保持不可用，不影响框架源码交付。
5. **训练作为独立后端能力。** runner 调用现有 `training/worker.py`；训练环境、基础模型目录与来源格式见 [训练 README](training/README.md)。用户在设置菜单调整权重、选择版本并另行确认后才可训练，不因打开页面或配置 API 自动开始。

完整请求示例及各动作所需权限见 [接入指南的 API 接入部分](coordination/对话沉淀与训练接入.md#6-api-接入)。部署时前后端须使用匹配协议；当前已有只读服务不在本次功能导入范围内自动升级或重启。

## 权重与训练设置

| 设置 | 默认值 | 可配置范围 |
| --- | --- | --- |
| 默认重要性 | `1` | `0` 至 `5` |
| 已采用次数增益 | `0.25` | `0` 至 `2` |
| 人工修订增益 | `1.5` | `1` 至 `3` |
| 单样本权重上限 | `6` | `1` 至 `10` |
| 逐节点重要性 | 未覆盖时使用默认重要性 | `0` 至 `5`；零表示不进入未来训练，不删除知识 |
| 学习率 | `0.0005` | `0.000001` 至 `0.005` |
| 训练步数 | `30` | `5` 至 `200` 的整数 |

前后端复用 [trainingWeight](src/contracts/intelligence.ts)，有效权重取三位小数：

```text
min(单样本权重上限,
    节点重要性
    * (1 + 已采用次数增益 * ln(1 + 当前节点版本的已批准采用次数))
    * (人工编辑过 ? 人工修订增益 : 1))
```

修改参数后先「保存设置」，再选择节点和训练模式、勾选本次范围同意、点击「开始训练」。设置或节点版本变化会使旧同意失效；重新读取不是自动批准新版本。一次最多选择 100 个节点，个人 LoRA 的有效非零样本须来自至少两段原始对话，不能把同一对话的切片同时当训练和独立验证。

| 模式 | 使用什么 | 完成后的用途 |
| --- | --- | --- |
| `smoke` | 内置 16 条合成样本、固定合成权重、随机初始化小模型；不读取个人节点 | 验证真实梯度和保存重载机制，始终不能启用为生产提取器；D 测试注入执行器，不运行该梯度任务 |
| `lora` | 用户已准备的本地基础模型，以及选中版本的确认知识和可核验原文 | 满足重载与独立验证门槛后，另行确认用于候选提取；不接管聊天、不自动改写知识 |

训练过程中可以读取状态，结束后在「训练记录」查看结果、单独启停适配器或清理产物。当前协议没有即时取消训练、自动重跑或断点续训动作；停用适配器不等于终止训练进程。中断进程尚未核验时不能清理。

## 运行

Node.js 最低 `22.13.0`，pnpm 固定为 `10.32.1`，以 [package.json](package.json) 为准。服务端使用 Node 内建 SQLite；旧环境记录中的实验性提示不应解释为跨平台兼容保证。

已有服务时先核对归属和版本，不在真实实例写入合成测试。非 watch API 不会因源码保存而升级。`1.31.0` 新 AI 页面拒收旧 API 缺失的身份绑定回显，须由维护者加载匹配前后端并重新连接，不能关闭校验。历史真实环境的限制见 [验证记录](docs/验证记录.md)。

独立使用且确认没有现有项目服务时，先安装依赖，再用 `pnpm local:start` 启动不读取私人 `.env` 的合成本机模式。它不自动接入你的模型配置。`pnpm local:status` / `pnpm local:stop` 只核验和管理该启动器持有的进程；显示「未托管」不代表没有其他项目服务。本轮安装和启停只由 A/运行维护者安排。

```sh
# 从克隆后的仓库根目录执行
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm local:start
pnpm local:status
```

打开启动器打印的 **Web** 地址。fixture 连接表单使用公开演示连接码（[LOCAL_DEMO_KEY](src/contracts/runtime.ts)，64 个 `f`），只用于 synthetic 工作区，绝不能当作 live 密钥。连接后先核对工作区、fixture 标记及契约版本，再按上方闭环操作。默认 fixture 可走人工导入/交接；不会从私人 `.env` 自动取得模型。既有 interactive fixture 若由维护者单独配置过本地 AI profile，会使用该已批准配置，不保证“fixture 永不调用模型”。

比赛合成演示的独立入口、地址与停止命令见 [演示与复现](docs/演示与复现.md)。请以启动器实际输出核对模式和版本。使用 `pnpm local:start` 的用户退出时执行 `pnpm local:stop`；直接运行的 `pnpm dev` 在所属终端停止，不能按端口盲杀。

需要真实工作区时，按 [运行与授权](coordination/运行与授权.md) 准备服务端 `.env`（普通文件、0600、已有文件不覆盖），随后由维护者运行 `pnpm dev`，按控制台 Web 地址访问。初始候选端口为 Web `4310` / API `4311`，占用时成对顺延；端口也可通过样例中的 `WEB_PORT` / `API_PORT` 显式传入进程环境。只给 OpenAI/本地模型变量不能跳过 CNB 工作区身份校验。live 连接框填 `ZHANGDUO_BOOTSTRAP_KEY`，不是 CNB Token。

### 配置哪些内容

只编辑用户提供的服务端配置，参考 [`.env.example`](.env.example)。已有 `.env` 不覆盖；文件必须非符号链接、权限 `0600`，不能向浏览器提供。下表列实际代码读取的变量，不包含真实凭据。

| 目标 | 服务端配置/环境 | 生效条件 |
| --- | --- | --- |
| 真实工作区 | `ZHANGDUO_MODE=live`、`ZHANGDUO_BOOTSTRAP_KEY=<独立生成的64位十六进制连接密钥>`、`ZHANGDUO_STATE_FILE`、`ZHANGDUO_STORAGE_CONFIRMED=true`、`ZHANGDUO_APP_SCOPES` | 数据库路径须为 `.local/live/<名称>.sqlite`；持久保存须用户同意，缺项保持 unconfigured |
| CNB 身份/读取 | `CNB_REPO_SLUG`、`CNB_TOKEN`、`CNB_TOKEN_SCOPES`、`CNB_LIVE_READS_FOR` | 由用户提供指定私人仓库；按仓库精确授权，不能在网页粘贴 CNB Token |
| CNB 写入/检索/索引 | `CNB_LIVE_WRITES_FOR`、`CNB_LIVE_QUERIES_FOR`、`CNB_LIVE_INDEX_FOR`、`CNB_INDEX_EMBEDDING_MODEL` | 分别批准；Issue/Git 写入不自动批准语义查询或索引流水线 |
| CNB AI | `CNB_AI_MODEL`、`CNB_LIVE_AI_FOR`、`CNB_LIVE_AI_PIPELINE_FOR`、`CNB_AI_OUTPUT_LIMIT_VERIFIED` | 能力核验后才配置为已授权，页面每次模型发送仍需同意 |
| OpenAI API | `ZHANGDUO_OPENAI_API_KEY`、`ZHANGDUO_OPENAI_MODEL` | 当前工程使用服务端 Responses 适配；模型标识由用户账号实际可用范围决定，不预填 |
| 本地兼容 API | `ZHANGDUO_LOCAL_AI_URL`、`ZHANGDUO_LOCAL_AI_MODEL` | 用户已有 loopback HTTP 服务；基础地址按该服务要求包含 `/v1`，不填完整 `/chat/completions` 路径 |
| 本地训练 | `training/.venv/bin/python`、`training/worker.py`、B 文档中的依赖 | 页面就绪标记只检查路径存在，不等于依赖导入或运行成功 |
| 个人知识 LoRA | `ZHANGDUO_TRAIN_BASE` | 已准备的本地基础模型绝对目录，具有模型、tokenizer 和 safetensors；文件检查不等于任意模型都能训练 |

未选择的提供方留空。项目不会搜索其他应用的密钥，不安装或改写现有本地模型服务，不自动下载模型。真实写入、模型调用和训练仍需对应权限及每次操作确认；只读配置不会因为页面增加按钮而自动扩权。

只读样例已包含总览需要的 `evidence:read` 和活动审计需要的 `audit:read`；这只修正 `.env.example`，不会修改已有 `.env` 或给当前会话扩权。按功能增补权限时参见 [最小权限表](coordination/功能状态与接口接入.md#5-最小权限)，不要一次开启全部写入、模型、导出和删除权限。

默认只读权限为 `workspace:read,conversation:read,candidate:read,draft:read,task:read,knowledge:read,evidence:read,settings:read,audit:read`。创建/归档需 `conversation:write`，发送再需 `model:answer`，设置/训练/启停需 `settings:write`，产物删除需 `data:delete`；正式节点、草稿、任务及证据仍按各自独立权限与批准办理。可选审核题目录 `ZHANGDUO_REVIEW_CATALOG_FILE`、核验工具 `CNB_VERIFY_*` 的范围见 [配置样例](.env.example) 和运行文档，不把核验工具授权当应用授权。

操作权限、完整 API 示例和故障处理见 [接入指南](coordination/对话沉淀与训练接入.md)；领域状态与适配器边界见 [功能状态与接口接入](coordination/功能状态与接口接入.md)。

## 数据与恢复边界

- 本机完整会话保留 30 天；每身份最多保留 100 个会话，每个会话最多 100 条消息。发送有额外内容范围限制，超过范围拒绝，不悄悄截断历史。
- 未发送草稿保存在当前页面内存，不承诺关闭或强制刷新后恢复。普通离开有草稿/未决操作保护，不向 localStorage 保存正文或批准。
- 模型发送、Issue 归档、Git 正式提交、训练、启用、停用和删除是不同操作，不能互相替代同意。
- 结果未知时保留原 operationId，通过「只读核验」查询；缺失回执不能当作未执行证明，不创建新编号重试同一副作用。
- 删除本机会话不删除已归档 Issue；零权重不删除 Git 知识；停用不删除适配器。训练产物位于 `.local/<fixture|live>/training/<workspace-sha256>/<run-id>/`，不放进前端静态目录。
- 节点撤回、删除或版本变化会使旧来源适配器资格失效。逻辑阻断和目录删除均不保证 SQLite/WAL、备份、外部模型、磁盘历史或第三方副本被物理擦除。
- 本轮 D 通过实际客户端/HTTP 注入验证身份绑定与闭环编排，不等于真实浏览器、模型或 CNB 通过。效果、知识正确和用户掌握仍须独立评估。

## 常见故障

| 现象 | 恢复步骤 |
| --- | --- |
| 无法连接 / 503 | 检查 Node 版本、控制台真实地址、工作区配置缺项和 `.env` 权限；未配置不是代码未实现 |
| AI 页面身份未核验 / 401 / 403 | 核对同版本前后端、当前工作区与 scopes，重新连接；不通过 URL/body 伪造身份 |
| 节点列表暂不可用 | 查看 `samplesStatus`；正式快照不可读不等于空库，聊天/设置可独立工作，LoRA 必须等来源恢复 |
| 409 / 版本变化 | 保留草稿，读原操作和对象当前版本，再人工比较与确认；不自动刷新 revision 重发 |
| 发送/归档/设置结果未知 | 点击「只读核验原操作」，核对原 ID、动作、摘要及回执；`not_found` 也不能证明未执行 |
| 模型无回复或训练失败 | 看原会话/run 状态；核对所选提供方或 [训练环境](training/README.md)，不换 ID 自动重试 |
| 不能启用或删除训练 | smoke 禁启用；LoRA 需完成、重载与独立验证通过、来源版本有效；删除还需 `cleanupReady=true` |

AI 原操作恢复只保留当前页面内存；身份失效隐藏正文并保留最小恢复摘要，强制刷新不保证恢复。未知时不要靠刷新、关闭页或换提供方判断未写入。
